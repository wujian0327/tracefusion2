# Go 单函数循环验证

## 当前状态与运行

新增普通 Go 循环场景，复用现有 `go-amd64-u32-leaf` 适配器、Go 构建器、BCC 采集器与 `loop_provenance.py` 的动态重放核心。**2026-10-03 用户主机 Go 1.25.4 / BCC 0.29.1 真实采集通过：456 条事件、24 次调用全部正确，原始事件重放一致。**本轮不加入循环中的函数调用。

```bash
cd ~/tracefusion2
git pull origin main
sudo env "PATH=$PATH" /usr/bin/python3 scripts/go_loop_provenance.py run
```

成功或失败均返回 `artifacts/go-loop-provenance-*.zip`。无需 Docker，沿用 Go/BCC 环境。仍使用普通优化，关闭实验包函数内联；无 `nosplit`、cgo、汇编目标函数或来源标签。

## 场景与真值

每个函数运行 `0、1、2、4` 次迭代，两个数值轮次，共 24 次入口调用。两个输入字段故意同值。真值由 Go 主程序按源码语义独立计算，只在评分时使用。

| 函数 | 零次循环 | 一次、两次 | 四次 |
| --- | --- | --- | --- |
| 加工 | 输出原敏感字段，来源为该字段 | 每轮 XOR 后加 3，仍来自敏感字段 | 保留逐次加工的执行版本 |
| 覆盖 | 输出常量 42，无输入来源 | 最终来自敏感字段 | 后两次使用公共字段，最终只保留公共来源 |
| 累积 | 输出常量 0，无输入来源 | 累积敏感字段 | 前两次敏感、后两次公共，最终保留两种来源 |

每个编译后的目标函数必须保留可达 CFG 环，否则构建检查失败。多次循环用例还必须有动态向后边证据。这里不把向后边数量直接等同于源码迭代次数，也不靠循环次数猜来源。

## 算法和编译器处理

全部目标指令位置挂接探针。重放器按实际事件顺序验证寄存器、标志位、内存及 CFG 转移，再为每次指令执行建立独立版本并反向提取贡献来源。复用原 C 循环算法，没有另写 Go 传播规则。超过 4096 条执行事件的单次调用明确失败，不截断后返回成功。

共用指令模型新增 32 位寄存器 INC/DEC，保留原进位标志；新增受支持条件的 32 位 CMOV，根据已验证的标志位选择实际值。内存源 CMOV 即使条件不成立也读取源操作数，但只有选中值对结果建立数据依赖。精确的 `XCHG AX,AX` 填充编码视为 NOP，其他 XCHG 仍拒绝。

Go 优化可能移动、合并读取或采用条件移动。因此本轮评分是**最终字段来源集合与输出值**，另检查重复执行证据；报告机器读取实例与贡献图，但不把源码每轮读取强行标成机器读取序号真值。汇编测试有明确机器读取语义，可以单独验证覆盖只保留最后贡献实例、累积保留各贡献实例。

本次编译的具体实例：零次覆盖输出 42、零次累积输出 0，均无输入来源；四次覆盖执行四次读取，最后仅 `input.public_value@read4` 贡献输出；四次累积保留敏感字段第 1/2 次读取与公共字段第 3/4 次读取；四次加工从一次敏感字段读取开始，图中保留四个不同执行版本的 XOR。

在这个二进制中，向后边次数恰好等于迭代次数，读取实例也可逐项核对；这是本次编译的性质，不作为跨编译版本的读取序号真值。主机执行了 42 次 INC；此构建没有 DEC/CMOV，后两者仍仅由本地独立 ISA 测试覆盖。此旧入口的单函数循环已验证。循环中调用 helper 现由新增 [C / Go 共用入口](loop-calls-provenance.md) 处理，两种语言均已通过真实采集。

## 本地验证

新增 7 项独立 ISA 测试通过，1 项实际 Go 编译测试因没有 Go 编译器跳过。ISA 输入由 GCC 汇编器构建，由 Unicorn 独立执行，不称为 Go 编译器输出或内核采集。

覆盖零/单/多次循环、同值来源、反复加工、覆盖消除、累积、条件移动、未见过的次数 3/7、函数重命名与加工常数变化。删除整轮并重排事件序号、缺失或重复事件、条件标志损坏、G 身份变化及超出事件预算均不能通过；额外用独立 CPU 模拟核查 INC/DEC 的进位保留和 CMOV32 的高位清零。

完整套件运行 97 项：91 项通过；3 项旧 HTTP 集成测试在创建本地 socket 时被当前执行环境以 `PermissionError` 阻止；3 项实际 Go 编译测试跳过。没有将完整套件记为全通过。

此外重放此前五个真实采集包，共 **1390 条事件、76 次根调用**。从实际 ELF 重新生成的计划、BPF 源码、完整推断和评分均保持一致，见 [旧包回归记录](go-loop-regression-20261003.json)。旧实验无需重跑。

边界仍是固定 uint32 字段、单个固定用户 goroutine、只读输入、无内部调用的目标函数。遇到不支持的指令、运行时调用或栈检查形式将拒绝。一般 goroutine 调度、字符串/切片、循环中调用 helper 和跨服务溯源尚未覆盖。

循环中的 helper 调用请使用 [新的共用核心与运行命令](loop-calls-provenance.md)；本文件的历史结果仅对应单函数入口。
