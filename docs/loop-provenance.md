# 单函数循环：执行实例与覆盖语义验证

这是跨函数实验之后单独验证循环的一步。本地模拟执行及原生夹具检查通过，**真实 BCC/eBPF 采集待主机验证**。跨函数实验的真实结果不等于本循环实验已经通过。

## 运行

```bash
git pull origin main
sudo /usr/bin/python3 scripts/loop_provenance.py run
```

沿用现有 Linux x86-64/WSL2、GCC/binutils 和系统 Python BCC，无需 Docker、无需在采集主机安装 Unicorn。成功或失败都返回 `artifacts/loop-provenance-*.zip`。只查看二进制计划可以运行 `python3 scripts/loop_provenance.py build`。

## 问题和真值

配置三个入口、输入和输出字段布局，不配置循环次数、循环体地址、函数名传播规则或预期来源。两个数据轮次，分别执行 0、1、2、4 次循环，共 24 次入口调用。敏感字段与普通字段故意同值。

| 场景 | 操作 | 执行 4 次时的最终来源 |
| --- | --- | --- |
| `loop_transform` | 循环前读取敏感字段；反复执行 XOR 和加法 | 最初那 1 次读取 |
| `loop_overwrite` | 前两次读取敏感字段，后两次读取普通字段，每次覆盖 x | 第 4 次读取，排除前三次 |
| `loop_accumulate` | 同样读取，但每次将值累加到 x | 全部 4 次读取 |

零次循环时，transform 仍有循环前的敏感读取；overwrite 输出常量 42，accumulate 输出常量 0，后两者没有输入来源。

`volatile` 输入用于确保夹具中的每次读取保留为实际机器指令，业务函数中没有加入日志、标签或追踪调用。这里的“读取实例”严格指本次入口执行中的**输入字段机器读取**，尚不是数据库查询实例。编号由离线分析器依据执行顺序生成，没有把标签写回程序。

`main.c` 独立生成预期来源字段、参与结果的读取序号以及预期输出值；该 stdout 仅供评估器读取，推断不读取真值。重复读取同一个字段也有不同实例：如 `input.public_value@read3` 和 `input.public_value@read4`。完整身份还包括所在的线程与入口调用编号，不能跨调用只比较这个局部字符串。

## 方法

1. 静态解码构建可含环的控制流图。本轮不枚举展开路径，也不猜测运行时循环次数；直接调用暂不纳入本循环验证器。
2. 使用已修正帧索引的跨函数采集器，观测范围内全部指令位置。事件序号区分同一探针的多次命中，采集寄存器、标志位及规定内存窗口。
3. 从入口逐事件重放机器状态，验证每一步后继、分支、寄存器和内存是否一致，最后必须完整返回。仅凭循环体探针命中次数不能判定传播正确。
4. 为每次执行的指令建立不同定义节点，为每次输入字段读取建立来源实例。覆盖替换旧依赖，累积保留并合并依赖，反复加工只传播已有依赖。
5. 从最终目标字段反向提取依赖图，并分别报告来源字段集合和实际参与结果的读取实例。`summary` 提供访问次数等摘要，原始展开图保留用于核对。

每次入口最多接受 4096 条指令事件，这是资源保护上限；超过时拒绝该次推断，不截断后给出成功结果。它不是静态展开次数，也不是夹具次数的硬编码。

后向跳转次数不是通用的源码循环次数，摘要中的 `backward_edges` 仅按机器控制流统计，不能直接命名为 iterations。图仍保留所有有关的执行版本，目前没有完成语义保持的循环图压缩。

## 本地验证（2026-10-01）

独立的 Unicorn 2.1.4 执行实际 ELF 机器码生成模拟观测；C 夹具另行原生执行产生评估输入。模拟事件不是由推断器自身生成。

- 完整测试 72 项通过，包含原有 66 项和新增 6 项；无跳过的模拟执行测试。
- GCC 13.3.0 构建：3 个函数，47 个物理探针位置，428 条模拟事件，24 次入口调用；每次最多 38 条指令事件。
- 来源字段关系 TP=22、FP=0、FN=0；来源读取实例关系 TP=28、FP=0、FN=0。
- 单独检查了四次覆盖后最终图只保留第四次来源，累积保留四个实例，循环加工中同一 XOR 位置形成四个不同定义。
- 删除完整的一次循环过程并重新编号事件，仍因状态不一致被拒绝；同时检查缺失返回、重复事件、寄存器/标志位/内存/IP/深度错误、丢事件、整次调用缺失及预算超限。
- 将第 4 次普通字段读取错误归因为第 3 次时，字段集合虽相同，读取实例评估仍失败。
- 所有函数改名、加工常量变化、循环次数换为 0、1、3、7 后仍通过，未改变推断规则。

以上仅为本地受控验证，真实采集结果待回传。当前观测全部范围内指令，未证明低开销。本轮不提供静态来源精确率基线，也不把来源集合指标当作完整图边准确率。

## 当前边界

单线程、输入内存不变、固定字段布局、已支持 x86-64 指令子集、单函数内循环。尚未验证循环和跨函数组合，也未覆盖数组动态索引、递归、堆对象、库函数、并发或跨服务。只处理显式数据依赖，不报告隐式控制污点，不进行代数消去意义上的最小因果来源证明。

结果文件沿用前阶段：`events.jsonl` 是原始证据；`inferred.json` 包含 `source_reads`（所有输入读取）、`contributing_reads`（最终来源）、`summary` 和 `dependency_graph`；`evaluation.json` 同时评分字段及读取实例；失败诊断和实际 ELF 一并保留。
