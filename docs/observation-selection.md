# 有界字段模型中的观测选择

本轮把已验证的三种采集策略接入一个可执行选择器。目标是在既定字段模型和环境前提下，选择足够的运行时证据，并说明为什么接受或拒绝某种策略。它不是通用程序的最小探针集合求解器。

## 输入与输出

输入是完整探针计划：经二进制核对的叶函数 IR/CFG、ABI 与数据区域约定、可用快照位置，以及额外运行时输入的配置。当前范围仍为四字节输出、有限指令集、无内部调用，以及最多一个独立控制字节。服务关联继续由现有 OTel/HTTP 拼接负责。

`observation_policy.choose_observation(plan)` 输出：

- `status`：`selected` 或 `unsupported`。
- `mode`：`boundary`、`entry`、`entry_replay`、`selective`，或拒绝时的 null。
- `analysis`：可达指令数、发现的控制输入读取地址、输出写入地址和运行时检查要求。
- `candidates`、`reason`：候选策略的接受/拒绝理由。
- `entry_stability`：入口复用所需的充分条件检查结果，仅在选中 entry 时出现。
- `assumptions`：完整数据区域模型、没有外部数据写入，以及控制输入私有持有等环境前提。

这些前提不因为自动选点就变成已证明的程序事实。尤其不会从普通 trace 或一个指针推导出“没有外部写入”。

## 步骤一：从 CFG 查找未覆盖的输入

分析器沿 CFG 传播寄存器的抽象类别：`src`、`aux`、`dst`、`control` 区域地址、标量，以及未知。从配置的入口 ABI 初始化状态，在分支汇合处取类别集合的并集，直到状态不再变化；只在一条路径有定义的寄存器，在另一条路径上仍保留未知。

复制和支持的地址运算传播地址区域，字节加载产生标量，条件跳转同时分析两条后继。它不会依据某一次执行的路径删除另一个候选分支。随后检查每个可达内存读取：

- 已声明数据区域中的读取由入口数据和模型内写入重建。
- 独立控制字节的比较读取属于尚未被原有边界快照覆盖的运行时输入。
- 未知地址、未初始化寄存器、不支持的控制输入别名或操作，不能被当成零值或任意已知来源。

地址区域类别是粗粒度抽象，不证明具体地址永远在区域内。执行重建仍检查每次实际读写地址、对象身份和范围；任一检查失败返回 unknown。

## 步骤二：选择证据策略

设 `R` 为分析得到的、需要额外观测的控制读取位置集合。选择流程如下：

| 检查结果 | 选择 | 理由 |
| --- | --- | --- |
| 出现未建模调用、未知输入、未建模的非输出区域写入，或控制输入缺少私有持有前提 | unsupported | 现有模型不能给出受支持的采集方案 |
| 模型检查通过且 `R` 为空 | boundary | 当前数据模型已覆盖所有可达读取 |
| `R` 非空、快照位置完整、入口复用证书成立且传输有快照槽位 | entry | 入口采样一次，后续比较复用 |
| 控制字节会变化，但支持的更新块通过完整性检查且其他前提成立 | entry_replay | 入口采初值，后续版本通过指令重放获得 |
| 控制读取可正确采集，但入口复用未获当前证书支持 | selective | 保留全部这些读取位置，在每次执行时获取证据 |

入口复用证书沿用 `stable_runtime_input`：支持的叶函数没有调用；控制基址不变；内存写入只能通过不变的输出基址；不跳回入口；运行时确认控制对象与数据对象分离、每次写入都在输出区域内。控制字节没有外部写入仍是显式环境前提。

`entry_replay` 使用独立的 `deterministic_runtime_input` 检查。目前允许声明模型内的连续“加载控制字节、与字节常数异或、写回”块，并在重建时更新状态；普通未支持的控制写入仍拒绝。具体场景、出口校验和边界限制见[控制翻转实验](gin-toggle-provenance.md)。它不要求变量数值不变，要求的是变化能够被现有模型和输入确定。

策略顺序是一个保守偏好，而非成本最优性证明。比如某个控制读取所在的分支可能根本没有执行，提前在入口采样未必比按需读取便宜。目前没有执行概率、频次估计或全局成本优化。

`unsupported` 不会被静默替换成 full。完整指令探针也不能自动补齐未知调用语义，更不能消除共享字节在 uprobe 采样与真实指令读取之间的竞争。调用方需要扩大模型或改变证据获取方式。

## 步骤三：生成计划与重建验证

`gin_byte_adapter.select_observation(plan, 'auto')` 根据选择结果生成真实采集计划，并保存 `observation_decision`。不支持时在挂载前拒绝。它复用已有模式的探针生成和同一个来源重建核心。

动态检查失败时返回 unknown。程序执行结束后无法凭空补采过去没有保存的事件；当前没有声称支持自动回溯补采或丢证据后的无损回退。

Gin choice runner 在构建目录保存 `auto-plan.json` 和 `observation-decision.json`。四模式实验的最后一组使用自动选择结果：这个固定场景预期上游选择 boundary，下游选择 entry；预期不符会使该实验失败，而不是强制覆盖选择器的判断。其余三组仍保留作对照。

## 反例检查与本轮验证

新增测试覆盖：

| 反例 | 预期 |
| --- | --- |
| 控制对象未声明私有，或声明共享 | unsupported，不声称逐次 uprobe 能解决读竞争 |
| 未建模调用、对控制对象写入、未知地址读取、跳出 CFG | unsupported |
| 比较读取的探针遗漏或快照规格错误 | unsupported |
| 某条路径读取未初始化寄存器或未定义条件标志 | unsupported |
| 静态选择通过，但运行时控制地址与输出区域重叠 | 重建返回 unknown |
| 输出地址先复制到另一个寄存器，再通过它写入 | 当前入口证书不支持，保守选择 selective；具体重建仍正确 |

最后一项用独立合成 IR 和事件轨迹验证，**不是已采集的新 Go 工作负载**。CFG 区域分析能够识别这个输出别名，但当前入口证书采用更严格的直接寻址条件；因此这只是保守回退示例，不能用来证明逐次采样不可避免。改进证书后，该情况也可能获准入口复用。

已用最近的四模式主机归档验证：选择器从真实 full 计划自动给上游选择 boundary、给下游选择 entry；生成的采集器可用已有接口构造。使用已捕获的 entry 组事件重建，8 个请求的逐字节来源与跨服务图保持一致。这里复用已有真实事件，没有新增主机性能测量。

只检查一个已有完整计划，无需 root/BCC：

```bash
python3 scripts/observation_policy.py --plan /absolute/path/to/full/plan.json
```

选择成功退出 0，拒绝退出 2。指定 `--output decision.json` 可保存结果。单元回归：

```bash
python3 -m unittest discover -s tests -p 'test_observation_policy.py' -v
```

本轮把经验规则变为可检查、可执行、可拒绝的有界策略。尚未完成通用字段/别名建模、所有权推导、动态新输入发现或全局最优观测选择；也不以这些小场景声称已经确立论文创新性。
