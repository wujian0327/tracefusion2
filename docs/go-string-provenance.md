# Go 字符串多来源溯源：第一阶段

目标是从一次 JSON 输出反向找到参与加工的读取实例。场景执行三次文件读取：A 为 phone，B 为 prefix，C 为 other；按请求中的 `UseOther` 选择 A 或 C，可通过 `CopyValue` 执行 `strings.Clone(selected)`，通过 `TrimValue` 执行 `strings.TrimPrefix(selected, "SA")`，随后计算 `prefix + selected`，输出 `{"result":"..."}`。本阶段只有一个进程、一个请求，不涉及跨服务。

## 运行

在已具备 BCC 和内核 BPF 支持的 Linux amd64 主机上运行。当前 ABI 适配器只接受 Go 1.25.4 或 1.25.5；使用能导入 BCC 的系统 Python。不需要 Docker。

```bash
cd ~/tracefusion2
git pull --ff-only
sudo env "PATH=$PATH" /usr/bin/python3 scripts/go_string_provenance.py run
```

如果 sudo 环境看不到指定的 Go，可以显式传入其绝对路径：

```bash
sudo env "PATH=$PATH" TRACEFUSION_GO=/usr/local/go/bin/go /usr/bin/python3 scripts/go_string_provenance.py run
```

脚本编译目标、生成探针计划、采集十一个用例、离线推断并评估。无论采集成功还是失败，都会打印 `Return this archive: ...zip`，请返回该 ZIP。产物默认位于 `artifacts/go-string-provenance-<时间>/`；请使用自动生成的新目录，或通过 `--output` 指定尚不存在的目录。

仅编译与检查观测位置，不需要 root：

```bash
python3 scripts/go_string_provenance.py build
```

## 观测和推断

这次新增的是字符串 API 摘要路径，没有把原有 uint32 指令解释器扩展成通用字符串解释器。

| 层 | 文件 | 职责 |
| --- | --- | --- |
| Go 适配 | `scripts/go_string_adapter.py` | 解析二进制直接调用，验证 ELF 偏移，根据指定 Go ABI 解码字符串指针和长度 |
| 采集 | `scripts/string_capture.py` | 在调用及其续接位置挂 uprobe，采集参数/返回值、进程与 goroutine 身份、时间及丢失计数 |
| 值依赖 | `scripts/value_lineage.py` | 将读取返回值定义为来源实例，利用复制、截取、拼接与 JSON 摘要建立实际观测依赖 |
| 共用图 | `scripts/lineage_graph.py` | 从输出反向遍历依赖边；旧 C/Go 循环溯源也复用这部分 |
| 运行与评估 | `scripts/go_string_provenance.py` | 编译、夹具、采集、离线推断、独立真值评分和打包 |

配置的操作模型为：

| 操作 | 观测输入/输出 | 依赖语义 |
| --- | --- | --- |
| `main.readValue` | 文件路径、返回的完整字符串 | 每次实际读取调用是一个新来源实例 |
| `strings.Clone` | 输入字符串、返回的新字符串 | 内容一致且存储身份不同，建立输入 → 复制结果依赖 |
| `strings.TrimPrefix` | 输入字符串、前缀、返回的子串 | 当前仅支持匹配的固定前缀 `SA` 及非空结果，验证子串地址并记录保留区间 |
| `runtime.concatstring2` | 左右字符串、返回字符串 | 返回值依赖两个输入，保留 left/right 角色 |
| `main.marshalResult` | 输入字符串、返回 JSON 字节 | 固定 `result` 字段的值依赖输入字符串 |

数据身份使用观测到的“地址 + 长度”，字节内容用于一致性校验，不按字符串相等直接认定来源。`source:1/2/3` 是读取调用的观测顺序编号，不是预先写进数据中的标签。报告附有每次读取的路径、长度、摘要和事件序号。

推断器只接收事件及探针计划；推断结果保存后，评估器才读取 `oracle.json`。真值来自受控夹具的已知程序语义，没有作为目标程序中的溯源标签传播。

目标程序没有追踪回调、来源编号或强制线程绑定。构建会对自身包禁用内联，以保留当前观测位置；依赖符号信息、指定编译器和显式函数摘要。因此本实验并不证明任意现成生产二进制都能直接支持。

## 检查什么

原有三个用例为普通不同值、三路输入完全同值、包含中文及 JSON 转义字符，均选择 A+B，排除 C。新增成对用例 `branch_phone` 与 `branch_other`，使用同一二进制、同一组输入文件，A=C=`SAME`，B=`+86`，只改变请求中的 `UseOther`。两个输出均为 `+86SAME`，但来源应分别是 A+B 与 B+C。

各扩展复用原采集器，为 Go 适配器添加标准库 API 参数/返回值定义，为推断器添加相应依赖模型。推断器不接收 `UseOther`、`CopyValue`、`TrimValue` 或真值；它根据拼接调用参数对应的已观测字符串身份建立依赖。Go 1.25.4 的本地构建使用条件移动指令选择参数，两条路径共用同一个拼接调用位置。这里验证数据输入选择，不重建选择条件本身的控制依赖。

`evaluation.json` 新增 `branch_pair`，检查输入路径相同、开关不同、二进制相同、输出相同、观测位置序列相同且来源随选择改变。各用例仍独立与真值比较；仅输出相等不能通过评估。

新增 `copy_phone` 与 `copy_other`，与对应 `branch_*` 使用相同输入文件、来源选择及二进制，唯一区别是启用复制。`copy_checks` 要求复制后的存储身份不同、来源和输出与不复制时一致，并验证两个复制用例依然能区分 A/C。

新增四个内容变化用例：`trim_phone`、`trim_other` 直接截取选中的字符串；`copy_trim_phone`、`copy_trim_other` 先复制再截取。沿用同一二进制和输入文件，`SAME` 去掉前缀 `SA` 后为 `ME`，输出为 `+86ME`。`trim_checks` 要求输出内容改变但原始来源保持一致，两种来源选择仍可区分。

不复制、不截取时依赖图应有四条语义边：B → 拼接的 left，被选中的 A 或 C → 拼接的 right，拼接 → JSON 值输入，JSON → 输出字段。复制时将“选中来源 → 拼接”替换为“选中来源 → 复制 → 拼接”，共五条语义边。直接截取也有五条边，复制后截取有六条边。评分分别报告来源关系的 TP/FP/FN、precision/recall，以及这些已建模操作边的 TP/FP/FN。它们不是完整指令级血缘准确率。截取用例另行比较 `source_byte_ranges` 与独立真值，范围错误也会导致评估失败。

截取模型检查返回值确实是输入地址加 2、长度减 2，并且字节内容等于输入后缀。随后从解码后的 JSON `result` 字符串反向传递半开字节区间：JSON 字符串值采用恒等映射，拼接按左右长度拆分，截取加上被去掉的前缀长度，复制保持偏移。最终预期 B 的 `[0,3)` 和被选中 A/C 的 `[2,4)` 贡献输出；被排除的另一个来源没有贡献区间。这里的区间按 UTF-8 字节计，不是字符序号或转义后的 JSON 线上字节位置。被去掉的 `SA` 仍参与了前缀匹配判断，当前范围只表达被保留到输出的数据字节，不包含这种控制依赖。

另有五个证据破坏检查：采集报错、缺少一次读取、缺少拼接返回、未知输入身份、JSON 内容不一致，均应返回 `unknown`。复制另有三个负向检查：删除整对复制事件、修改复制结果内容、让复制结果复用旧身份，均应返回 `unknown`。删除复制事件后虽符合“不复制”的事件序列，但拼接参数的新地址没有已观测定义，因此仍不能归因。

截取再增加四个负向检查：删除截取事件、修改截取结果内容、修改返回地址、将截取输入改为未知身份。总计十二个负向检查，均要求 `unknown`。

这只验证已声明观测契约的缺失和矛盾，不保证发现所有未观测到的内部写入。

当前 Go 1.25.4 本地二进制规划为 16 个逻辑事件位置、15 个物理探针：拼接返回位置与 JSON 调用位置重合，必须由同一探针按顺序发出两个事件。前五个用例各 12 个事件，两个复制用例和两个直接截取用例各 14 个事件，两个复制后截取用例各 16 个事件，总计应为 148 个事件；收到事件仍不代表依赖图必然正确，需同时查看评估。

关键产物：

- `plan.json`、`disassembly.txt`、`symbols.txt`、`build.json`：二进制与观测位置。
- `<用例>/events.json`、`collector.c`、`target.stdout`、`target.stderr`：原始观测、采集代码及程序输出。
- `<用例>/inference.json`：反向切片、贡献来源及被排除的读取。
- `evaluation.json`：独立真值比较及负向检查；采集失败时查看对应 `.log` 与 `runner-error.txt`。

## 当前边界与验证状态

只支持本夹具声明的三次读取、零或一次复制、零或一次截取、一次拼接、一次 JSON 操作序列；读取来源指一次 `readValue` 调用及其返回完整字符串，不是数据库内部表、行、历史版本或文件系统调用级血缘。JSON key `result` 为固定模型的一部分，未重建动态 key 的来源。

来源字符串限 2–128 字节，单个快照最多 512 字节。当前要求存储身份独立且在观测区间内有效；发现重复身份或已定义值内容变化时拒绝归因。尚未覆盖一般别名、可变缓冲区、内存回收复用、任意库函数、跨请求并发或跨服务传输。程序不固定线程，事件要求来自同一进程和 goroutine；这次测试没有证明发生过真实线程迁移。

提交前已完成：Go 1.25.4 真实编译、三个用例直接运行、七项单元测试，以及旧 C/Go 共 884 条事件、48 次调用的回放，旧推断结果与保存结果完全一致。测试还修改同值输入的观测身份，确认推断会随证据改变，并被原始真值评分判错。

第一版已在用户的 WSL2 / Go 1.25.4 / BCC 0.29.1 主机通过真实采集：结果包 `go-string-provenance-20261004-063528-535795.zip` 的三个用例共 36 条事件，无丢失、无读取错误，每例两个来源关系及四条语义边均符合真值，五个负向检查通过。本地重放与保存结果一致。该结果仅适用于第一版三个固定选择用例。

运行时选择版已通过主机采集：结果包 `go-string-provenance-20261004-070038-104617.zip` 的五个用例共 60 条事件，无丢失或读取错误。成对用例输出相同 JSON，实际拼接参数分别对应 A 和 C，归因随选择切换。

复制版已通过主机采集：结果包 `go-string-provenance-20261004-071800-990801.zip` 的七个用例共 88 条事件，无丢失或读取错误；真实复制后地址不同，拼接使用新地址，两个复制用例分别归因 A+B、C+B。八个负向检查通过。

截取版已通过主机采集：结果包 `go-string-provenance-20261004-073456-122352.zip` 的十一个用例共 148 条事件，无丢失或读取错误。52 条已建模依赖边、四个截取用例的来源字节区间均符合真值，十二个负向检查通过。本地重新推断与保存报告一致。下一阶段的自定义字节函数指令实验参见 `go-byte-provenance.md`，其新的真实采集尚待独立验证。

复制模型依赖所选标准库 API 的语义，不会仅因两个地址内容相同就添加复制边，也没有逐条重建库内部内存拷贝指令。只新增了当前 `TrimPrefix` 的已知子串视图；不支持任意未配置复制/截取函数、一般别名、可变缓冲区版本或一般控制依赖。前缀不匹配、其他前缀、空结果均在当前截取范围之外。可选复制和截取的位置及允许的四条事件序列是本夹具的观测契约；规划器会拒绝直接跳转目标与可选操作返回探针位置重合的二进制，尚非通用控制流覆盖证明。
