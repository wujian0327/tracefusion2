# 论文范围与下一阶段验收

日期：2026-10-08。状态：研究与实验协议，不是新增功能验收报告。

## 稳定主线

**结合二进制分析与选择性运行观测，在无需修改应用源码或离线重写可执行文件的条件下，重建跨服务输出字段在本次执行中的实际来源依赖。**

先完成一篇范围适中、证据完整的论文，再由方法与实验结果决定投稿目标。部署便利、来源正确性和运行成本分别提供证据；不要求每一步实现都对应新算法，也不把已有能力的组合直接宣布为研究创新。

本阶段以 Linux/amd64、固定版本 Go 和同步 RPC 为实现范围。已有 C 适配和 Gin 微型场景作为回归资产；暂不扩大语言覆盖、数据库内部血缘、跨用户共享状态或隐式信息流。安全应用保留为跨服务敏感输出的来源审计，不预设存在真实漏洞，不通过人为削弱脱敏或 trace 制造优势。

## 查询与正确性的定义

基本查询是：给定一个已经被观测的请求实例及其输出字段，该字段实际依赖哪些源读取或 RPC 返回实例中的字段？数据相同不代表来源实例相同。

源身份至少包含服务/进程实例、请求或调用实例、读取或返回事件、字段路径；必要时包含字节范围。对象地址用于绑定运行时实例，不能单独作为跨生命周期的永久身份。覆盖产生新的定义；多输入加工允许返回来源集合。常量字段的空来源集合和证据不足的 `unknown` 必须区分。

阶段一回答显式数据来源。条件决定采用哪个定义，但不自动把条件变量列为输出的数据来源。每条跨服务边需要发送字段、接收字段与具体通信实例的关联证据；trace/span 只解决请求/调用关联，不能单独证明字段对应关系。

最终来源准确，不等于完整中间执行路径准确。只观测到足以确定最终来源的事件时，输出来源关系及其证据；没有证据的中间赋值、加工步骤不补成“实际路径”。加工内部未分析时，明确停在该调用返回字段或标为未知，不默认返回值依赖全部参数。

| 无需重写应用 | 现有采集采用外部探针，无需改写 ELF 文件 | 正常优化编译产物的支持程度；符号/调试信息、配置与权限需求 |

对应证据见 [真实函数审计](checkout-origin-audit.md) 和 [观测策略对比](gin-provenance-comparison.md)。这些记录保留负结果，不因调整论文目标而改变。

“无需修改”指不修改业务源码、不离线重写或替换目标 ELF；普通 uprobes 仍是内核管理的动态插桩，不表述为完全无插桩或完全不改变运行中指令。当前关闭内联的实验不能证明任意现有部署都可直接使用。若真实服务必须为本系统重新编译，应如实收缩部署主张。

已有 OTel 可复用；需要新增 SDK、修改上下文传播或重建镜像时，将其单独计入端到端部署要求，不能只计算 eBPF 部分的应用改动。开始观测前的历史来源不能事后凭空恢复。

## 下一里程碑：真实订单字段的局部来源

固定 Online Boutique v0.10.4 / `474d0f2eb73d97525234995a40d7781b7923a07d`，Go 1.25.4，目标为原始 `checkoutservice.prepOrderItems`。优先针对已审计的默认优化产物，不把禁用内联当默认前提。这个里程碑是实际系统的接入验证，不是完整商店部署或完整跨服务血缘验收。

先完成三类关系：

| 查询对象 | 目标来源 | 必须保留的身份 |
| --- | --- | --- |
| `out[i].Item` | 本次调用的实际 `items[i]` 对象 | 调用实例、切片元素与对象身份 |
| `out[i].Cost` | 本轮币种转换调用返回对象 | 具体调用/返回实例，不能仅靠价格相等 |
| 币种转换输入的 `From` | 本轮商品返回对象的 `PriceUsd` | GetProduct 返回实例与后续参数绑定 |

其中 Cost 首先追到本地 `convertCurrency` 返回。只有进一步验证该函数内部与 RPC 返回之间的传递，才能将来源延伸到具体 Convert RPC 返回字段。币种服务内部汇率、价格加工不凭该函数调用关系推断。

交付顺序：

1. **默认产物分析**：从机器码提取目标字段的读写/传递关系；声明所用 ABI、类型布局与函数摘要。允许配置目标字段、调用边界和布局，不将 `out[i]` 的正确来源答案写入配置。缺少布局/符号或遇到未建模指令时保留具体原因。
2. **运行实例绑定**：在必要的入口、调用/返回或写入位置采集对象和调用实例证据。复用现有 Go G/调用状态经验，重新检验动态容器与重复调用，不能直接宣称既有线程迁移结果自动覆盖新函数。
3. **独立真值对照**：复用已建立的原函数测试夹具；真值记录与分析器输入隔离。测试用拦截器可提供核对答案，但正式来源推断不能读取这些答案。
4. **原始证据验收**：本地完成静态与离线检查，再提供一个主机命令运行真实 BPF 采集。归档保留二进制身份、计划、原始事件、完整性计数、来源结果和真值。

验收沿用六组真实函数用例：0、1、8、32 个条目，以及第二次商品/币种调用失败。必须保留相同内容的不同对象；失败返回不能把途中构建的条目计为正常输出。增加必要事件缺失、错误调用配对或未知指令的负例，要求拒绝或 `unknown`，不能错误归因。

此有限验收集要求已声明支持的查询全部与独立真值一致；超出边界的查询单列。这个要求不是对任意 Go 程序的正确率保证。若首阶段只有对象引用关系，就标为对象引用来源，不提前宣称对象所有字段的历史血缘均已恢复。

退出条件：完成上面的三类关系和证据闭环后，停止在此函数追加微型变体，进入通信字段绑定与性能测量。若默认产物存在具体障碍，报告其范围及所需摘要，决定收缩支持范围或修复；不以改写业务函数、放宽真值或只提高指令数上限替代解决。

## 后续实验如何支撑论文

| 实验轴 | 对照/测量 | 公平性要求 |
| --- | --- | --- |
| 来源正确性 | 每次请求的字段来源集合，与独立真值比较 | 同值不同源、动态选择、覆盖、多输入依赖；输出错误和失败请求单列 |
| 观测选择 | 较完整记录、普通来源集合分析、路径敏感分析、当前策略 | 相同二进制、采集器、ABI/库摘要与查询口径；打平如实报告 |
| 部署方式 | 静态重写、DBI、外部探针的实际要求和适配工作 | 能运行才报实测；不能运行则记录兼容障碍，不当作精度或性能胜出 |
| 运行成本 | 无追溯、仅公共 trace、外部采集、完整重建；有条件再加可运行文献系统 | 相同业务、负载与公共 trace；区分在线和离线成本 |
| 适用范围 | 正常优化、编译版本、符号/调试信息与人工摘要需求 | 失败也计入覆盖范围，不只报告能分析的函数 |

来源集合指标同时报告：关系级 precision/recall、全部有效查询上的集合完全一致率、确定回答覆盖率、unknown 数与错误归因数。无来源常量查询单列；`unknown` 不视为正确空集合。避免只在已回答子集上报高准确率，也不把采集失败静默从分母删掉。对象级、字段级和字节级指标分表，不混合粒度。

性能先测无采集/仅公共 trace/选择性采集三组，再按可运行情况加入其它系统。同一负载先预热，随机化组顺序，至少五轮独立测量并公开每轮请求数、持续时间、硬件、版本、并发与失败率；具体负载参数在首次性能运行前固定。报告 p50/p95/p99、吞吐、CPU/内存、事件数和实际传输/存储量，保留原始数据与波动。不能从短夹具的八个请求或少几个事件推导生产性能优势。

完整跨服务阶段才将局部来源通过通信证据接起来。允许正确配置的 trace 基线；此前发现的 `context.TODO()` 断链不能故意保留作为优势。手工配置和框架适配的数量、修改范围及耗时如实记录。

## 贡献与停止扩张的原则

候选贡献是“无需应用重写的来源重建方法及其实证效果”，不是“首次使用 eBPF”或“首次静态加动态”。若观测策略没有超过强基线，可以采用合理的已有分析能力，把论文重点放在部署约束下的可实现性、来源精度与成本；只有获得新的证据，才增加新的算法贡献主张。

论文成稿前至少补齐：一个真实应用中有限范围的完整来源案例、明确的支持/失败边界、公平方法对照和受控性能实验。当前真实函数局部里程碑完成后，再判断需要增加多少应用；不预先将一个局部案例等同于足够的泛化证据。投稿档次由最终证据决定，不再为目标会议反复更换安全情节。
