# 默认优化 Go 二进制的对象依赖候选图

日期：2026-10-08。本轮完成 [研究协议](research-scope.md) 中真实订单函数接入的第一部分：从已有 ELF 提取对象读写和寄存器/栈槽定义依赖。没有运行新的 BPF 采集，没有完成请求实例级来源重建。

## 输入与实测结果

输入为此前审计构建的 Online Boutique v0.10.4 原始 `checkoutservice`，Go 1.25.4、Linux/amd64、默认优化，**没有为本轮分析重新编译应用，也没有关闭内联**。ELF SHA256 为 `d5668e6bce805073aab2f452f821745d7e0a2944ff20f52d2e0ad549f379409f`。本轮读取应用的 ELF、符号和其中的 DWARF，不读取应用源码或测试真值。

| 函数 | 与 ELF 核对的全函数指令 | 建立栈帧后的可达指令 | 堆/间接写入站点 |
| --- | ---: | ---: | ---: |
| `prepOrderItems` | 196 | 172 | 10 |
| `convertCurrency` | 73 | 54 | 5 |

指令数之差是函数序言和入口栈增长重试代码，不是采集节省。写入站点包含 GC 写屏障缓冲区写入，不代表同等数量的业务字段。本轮不记录动态执行次数，不据此估计 BPF 开销。

DWARF 自动读出 `OrderItem.Item=40`、`OrderItem.Cost=48`、`Product.PriceUsd=104`、`CurrencyConversionRequest.From=40` 等字段偏移。类型由完整限定名选择，避免把同名切片布局当作对象布局。**类型目录与对象分配点的自动绑定尚未完成**：依赖图自身用寄存器、内存偏移和分配站点表达；下面的业务字段解释由独立源码审计及布局核对提供，不能称作分析器已自动识别全部业务类型。

## 自动提取到了什么

在当前栈/调用约束下，提取结果与独立预期一致：

- 同一个新分配对象的 `+40` 写入值，来自输入切片的一次元素指针加载。
- 该对象的 `+48` 写入值，来自 `convertCurrency` 的 AX 返回值。
- 该对象随后写入新分配的结果切片；输入加载和输出写入的索引依赖终点相同。
- 传给 `convertCurrency` 的 DI 有两个静态候选：GetProduct 返回对象 `+104` 的加载结果，以及 nil 常量。保留两个候选，不用源码预期排除空对象分支。
- 在 `convertCurrency` 内，DI 写入请求对象 `+40`，该请求对象传给 Convert；正常返回路径保留 Convert 的 AX 返回值，错误路径返回 nil。

这些是静态定义和候选关系。分配站点在循环中可执行多次，不能充当动态对象身份；相同的索引依赖也不构成跨迭代对象绑定证明。尚不能回答“本次响应的这个字段究竟来自第几次 RPC”。

## 算法与共用核心的关系

新增 `scripts/go_object_graph.py`，独立于既有四字节来源核心：

1. 解析反汇编并构建函数体 CFG。拒绝未知指令、间接调用、跳出已建立栈帧的分支和当前不能处理的局部栈写入。
2. 对通用寄存器和对齐的八字节栈槽做 reaching-definitions 不动点分析。写入覆盖旧定义，分支合流取并集；循环通过有限定义集合收敛，不枚举迭代次数。
3. 生成定义—使用图，区分复制、常量、运算、堆加载、分配、调用返回与未知寄存器值。数值依赖和地址依赖分开保存。
4. 只沿完整八字节复制边展开来源终点。函数返回是独立未知边界，**不自动连到所有实参**。堆加载保留地址与观测义务，不假装已经恢复堆内存版本。

采用 Go 1.25.4 的运行时契约处理 `gcWriteBarrier1..8`：保留通用寄存器的值来源，R11 记录为屏障缓冲区指针，向量寄存器保守视为被破坏。依据为固定工具链 `src/runtime/asm_amd64.s` 的实现；它是运行时适配知识，不是本轮新算法。普通调用不使用这个特殊保存规则。

CLI 对反汇编每条指令核对 ELF 字节，并核对整个符号的起止边界；分析前后检查目标文件保持不变。现阶段读取符号和 DWARF 是明确部署要求，不能宣传支持任意剥离符号的生产程序。

## 为什么结果明确标为 conditional_static_candidates

当前分析保留栈槽复制关系，前提是这些私有保存槽没有经别名被被调函数或其它线程写入。程序中存在栈地址构造，因此这个前提**还没有由分析器完整证明**。结果显式列出构造栈地址的位置和调用副作用验证义务；不允许直接将其当作动态来源证书。

遇到未知指令或间接调用会拒绝；遇到尚未验证的别名/副作用条件则返回带条件的候选图。这与“系统能检测一切未建模写入”不同。目前尚不能检测任意隐藏写入，不能对实际运行自动声称安全回退为 unknown。

接入采集前需要分别处理：私有栈槽是否逃逸及调用写范围、动态对象/调用身份、循环实例绑定和必要的堆读写版本。单纯比较调用前后数值相等不能排除同值覆盖，不能据此证明来源未改变。

现有共用来源核心和采集器不受修改；后续明确好上述义务后，再设计对象事件接口接入，避免把寄存器候选图直接当作已有字节核心支持了一般对象。

## 验证及明确失败

14 项针对性测试通过，包括赋值覆盖、分支合流、循环收敛、普通调用破坏寄存器、写屏障、常量、未知指令/间接调用拒绝、栈地址逃逸义务以及真实汇编中的关系。真实汇编中一处返回值保存被测试替换为常量后，提取结果随之改变，检查没有按函数名称写死来源答案；该变体仅是解码层测试，不宣称仍与原 ELF 匹配。

两项独立负检查：

- 同一应用关闭内联的产物遇到 `CALL DX`，明确拒绝，未声明兼容。
- 在专门的负例副本中移除 DWARF 后，布局读取明确失败；原始目标 ELF 未修改。

这些结果不表示来源准确率为 100%，也不构成性能对比。机器记录见 [本地验证汇总](checkout-object-graph-local.json)。汇编回归夹具来自固定原始构建，出处与哈希见 `tests/fixtures/checkout-object-graph-origin.json`。

## 复现与下一步

使用此前审计生成的默认优化二进制，或先按 [真实函数审计](checkout-origin-audit.md) 构建：

```bash
python3 experiments/checkout-origin-audit/analyze_binary.py \
  --binary artifacts/<此前审计目录>/checkout-default \
  --go /path/to/go1.25.4/bin/go \
  --output artifacts/checkout-object-graph.json
python3 -m unittest discover -s tests -p test_go_object_graph.py -v
```

输出文件要求不存在，以免覆盖旧证据。报告保留 CFG、定义节点、写入/调用/返回站点、字段布局以及未履行的义务。输出字段 `allocation_type_binding_complete`、`bpf_capture_executed`、`dynamic_provenance_complete` 均为 false。

**下一步是约束并验证栈槽/调用副作用，确定对象实例观测接口，再接真实 BPF 采集。**本轮无需用户启动新的主机实验；不能把这份静态图交给旧采集器就声称已跑通真实订单溯源。
