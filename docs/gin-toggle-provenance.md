# 循环内控制状态变化：初值观测与更新重放

本实验检验：**控制变量发生变化，不意味着每次变化都需要重新采样；如果更新可以由已有输入和已建模指令推导，就能重建它的后续版本。**

继续复用两个 Gin 服务、四字节字段和 OTel。下游的区别只有循环中的控制更新：

```go
for i := 0; i < 4; i++ {
    if *control == 0 { dst[i] = src[i] } else { dst[i] = other[i] }
    *control ^= 1
}
```

初值为 0 时，四个输出位置分别来自上游、本地、上游、本地；初值为 1 时相反。所有数据源在正式采集中仍为 `SAME`，不能用值匹配区分来源。真值规则只在评价阶段使用。

## 主机运行

```bash
cd ~/tracefusion2
git pull --ff-only
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 scripts/gin_choice_provenance.py run --variant toggle
```

返回打印的 `artifacts/gin-toggle-provenance-*.zip`，失败也返回。默认不带 `--variant toggle` 仍运行原有稳定控制字节场景。

| 模式 | 控制输入的处理 | 本轮预期 |
| --- | --- | --- |
| full | 保留已建模的全部内部指令事件 | 正确还原交替来源 |
| boundary | 原有边界，没有入口控制初值 | 当前前向重建器返回 unknown |
| selective | 保留比较读取和更新前加载这两个位置 | 每请求 8 条控制读取事件，来源正确 |
| entry_replay | 入口采初值一次，按指令重建后续版本 | 每请求 1 条入口事件，与 full/selective 逐字节来源一致 |

最后一组通过自动选择器生成计划：上游为 boundary，下游为 entry_replay。三种成功模式必须使用同一组二进制，并通过独立的逐字节来源真值检查。旧 `entry` 模式意味着重复使用不变值，必须被拒绝；拒绝原因保存到 `stable-entry-rejection.json`。

## 实现

固定 Go 工具链实际将翻转编译为三条指令：读取控制字节到寄存器、寄存器与常数 1 异或、写回控制字节。本轮沿用已有 MOVZX/XOR/MOVB 指令解释，没有把“奇数轮选上游、偶数轮选本地”编码进溯源核心。

`deterministic_runtime_input` 检查受支持的连续加载/异或字节常数/写回块，并拒绝从中间进入该块的分支。其余指令继续接受原有的区域、基址、无调用和私有持有条件检查。当前只开放这种受支持的控制更新形态，没有宣称任意加工函数都能重放。

共用 ByteMachine 为每个请求独立保存控制值和版本。普通数据字节仍沿原有依赖图传播；控制写回不会计入输出字段的赋值次数。

- full/selective：每次实际控制读取都与此前重放的更新结果核对，出现矛盾返回 unknown。
- entry_replay：从一次入口快照初始化，再解释每条更新指令，比较时读取当前版本。
- 三种成功模式：函数返回时额外读取控制字节，核对最终内存状态；该快照附加到已有返回事件，不新增事件位置。

`inference.json` 的 `runtime_control_updates` 保存版本、前后值、指令位置和证据类型；`final_runtime_control` 保存最终状态。entry_replay 的比较步骤标记 `replayed-control-version`，避免将推导出的中间状态当成实际采样值。来源图仍表达显式数据依赖，没有扩展成完整隐式流追踪。

## 验证与边界

本地已完成实际 Go/Gin 构建与四种计划生成。独立手写的执行轨迹验证了两种初值、四次翻转、交错请求状态隔离、逐字节来源及 HTTP/SDK 拼接；缺失事件、错误初值、矛盾的中间读取或出口状态必须拒绝。

原生 HTTP 测试将本地 B 临时设为 `LOCL`，得到与逐字节交替规则相符的响应，以确认真实程序确实切换来源；正式 BPF 采集仍全部使用相同值 `SAME`。此前稳定控制字节场景的四模式主机归档重新解析后结果不变。本轮新场景的 BCC 采集仍待主机验证。

如果更新依赖新的未观测输入、未知调用、未支持的运算或写入形态，自动选择器会拒绝当前优化。对象私有持有、没有外部写入依然是环境前提；本轮未增加共享内存竞争支持。

**本轮检验的是前向状态重建，不证明入口探针在信息论上必不可少。**当前完整寄存器/返回快照可能暴露可用于逆向约束初值的信息；例如四次翻转后控制字节回到初值。当前 boundary 算法尚未利用这类出口约束反推入口，所以它返回 unknown 不能被解释为所有边界分析都无法归因。本轮也不报告最少观测数或性能收益。
