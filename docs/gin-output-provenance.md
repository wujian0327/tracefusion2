# 根据最终输出来源省略控制观测

本轮验证：前面的来源选择如果被后续赋值完整覆盖，就无需为**最终来源**观察那个选择。它不恢复被省略的真实中间路径。

## 主机执行

```bash
cd ~/tracefusion2
git pull --ff-only
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 scripts/gin_output_provenance.py run
```

返回最后打印的 `artifacts/gin-output-provenance-*.zip`，失败也返回。沿用前几轮的 Go 1.25.4、Gin、BCC 和 OTel 环境，不需要新容器。依次构建三组，每组有 full、boundary、auto 三次运行，每次八个请求。只构建使用 `build`；也可通过原 runner 的 `--variant kill-full`、`kill-partial`、`kill-none` 分别运行。

归档保留 build 下的二进制，内容相同的文件以 `binary-aliases.json` 记录原路径、保留路径和 SHA256；各试验目录仍保留计划和原始事件。失败结果包也会保存。

## 三个对照

下游先循环四次，按同一个请求私有控制字节，从上游字段或本地字段复制到输出。

| 场景 | 后续操作 | 仍依赖条件的输出位置（从 0 开始） | 自动策略预期 |
| --- | --- | --- | --- |
| kill-full | 四个字节重新从上游复制 | 无 | output：无内部探针 |
| kill-partial | 只重写最后两个字节 | 0、1 | entry：采控制初值一次 |
| kill-none | 不再重写 | 0、1、2、3 | entry：采控制初值一次 |

所有正式 BPF 数据源仍为 `SAME`，来源正确性不能靠值匹配。full 采集完整受支持指令，作为最终逐字节来源的对照。旧 boundary 仍尝试正向恢复整个执行过程，遇到未知条件会返回 unknown；output 改为回答最终来源问题，并不因此宣称恢复了完整执行路径。

## 算法

新增 `output_dependence.py`，输入来自二进制解码的 IR/CFG，不读取场景名或手工填写输出来源关系。当前是一个明确受限的实现：

1. 限定一个不变的私有控制字节，且仅用于与零比较并执行等于/不等于分支。由此将全部 256 个可能值分为零、非零两类。
2. 对两类分别做有界符号执行。来源用 `(区域, 字节偏移)` 表示；未知数据值不会被替换成 `SAME`。循环计数必须可计算，数据操作限定为支持的字节复制，最多 64 条静态指令、每类最多 256 步。
3. 记录每个输出字节的写定义，逆序扫描得到最后写入及被覆盖写入。复制已写输出时继续传播此前来源，不能仅根据“最后有一次写入”判定旧来源消失。
4. 比较两类执行的最终逐字节来源。只有全部相同才生成输出投影证书；有不同位置则保留控制证据。当前部分覆盖仍回退到原有 entry 策略，没有进一步省略部分动态迭代的事件。

这是有界符号执行和最后写定义分析的实现，不是通用程序的后向切片器或最小探针求解器。未知调用、数据相关索引/条件、无法处理的运算或循环超界会拒绝这份证书；选择器随后尝试原有策略，不能通过把错误结果当成功来省略观测。

## 运行时绑定与结果语义

新的 output 模式保留实际读取、调用返回、序列化、发送/接收以及 OTel 边界。重建时重新计算证书，核对实际对象身份和完整区域不重叠，将符号来源绑定到本次请求的实际读取对象，并检查已知出口寄存器和最终 JSON 内容。

图中省略部分以 `certified-output-dependency` 表示。来源节点仍来自实际采集，不来自测试真值。`instruction_steps` 为空，`execution_history` 为 `not_reconstructed`；`source_versions`、`overwritten_sources`、`total_writes` 为 null，避免把某一条假想路径记成实际历史。证书中的两类路径是静态证明材料，不是运行时观测。

保证依赖明确的模型前提：输入数据和控制区域执行期间没有外部写入；对象不重叠；完整受支持函数成功返回。事件缺失、身份冲突、证书与 IR 不一致或最终值不符时返回 unknown。没有增加未知共享写入检测或任意别名支持。

## 已完成验证

- 三种真实 Go/Gin 构建均由自动策略得到预期结果，完全覆盖没有被编译器直接删成一个无分支函数。
- 使用 Unicorn 独立执行编译后的机器码，覆盖控制值 0、1、127、128、255；输出投影/入口观测与完整轨迹逐字节来源一致。
- 检查部分覆盖、无覆盖、未知效果、错误条件分区、超界循环、证书篡改、错误对象/出口值、交错请求和 HTTP/OTel 来源图拼接。
- 三组真实 HTTP 测试将本地字段临时设为 `LOCL`，确认覆盖行为；正式采集保持等值数据。
- 前两轮主机归档重新解析后，报告与来源图保持不变。

本轮真实 BPF 事件数仍待主机验证。这里比较的是最终来源正确性和采集量，不把中间历史缺失说成无损恢复，也不据此宣称已建立论文创新性。
