# 真实文件读取到输出字段的来源绑定

## 当前状态与运行

新增 C 文件读取场景，将真实 `pread64` 的返回字节连接到既有循环/调用依赖图。**本地编译、原生 C 真值、实际文件操作及独立指令执行已验证；BCC 编译、内核挂接和真实事件流尚待主机验证。**这一轮只接 C，来源表示及绑定逻辑独立于 C 调用约定，Go 尚未接入本场景。

```bash
cd ~/tracefusion2
git pull origin main
sudo /usr/bin/python3 scripts/read_provenance.py run
```

无需 Docker 或新安装包，沿用 GCC、binutils、系统 Python BCC。返回 `artifacts/read-provenance-*.zip`，成功和失败都保留包。旧 C / Go 实验不用重跑。

## 本轮具体推进了什么

原引擎能从输出回到 `input.left` 的一次机器读取。本轮继续向前连接：**哪个文件描述符对应的文件、哪一次 pread、哪个文件偏移区间，产生了这次机器读取使用的字节。**不根据数值相等猜测来源。

范围分为两段：

- 读取阶段：在工作负载范围内观察系统调用的进入和返回，不解释 libc 的内部机器指令。
- 计算阶段：复用 `loop_calls_provenance.py` 的指令验证、调用实例、读写版本和反向依赖图。计算根函数执行期间输入仍为只读，不允许在其中发生读取。

当前输出仍是配置的内存字段，不是网络响应。文件身份不等于数据库表/行身份，文件字节区间也不是自动恢复的业务字段名。

## 采集和来源表示

`read_provenance.py` 在目标进程停止时，通过其 `/proc/<pid>/fd` 和 `fdinfo` 快照记录预先打开的普通文件：fd、路径、device/inode、大小和访问模式。成功读取仅接受已知的只读 fd。

普通工作负载函数 `run_workload` 的入口和返回设置观测范围；没有加入日志埋点、trace ID、来源标签或探针调用。入口 uprobe 限定到子进程 PID，并在内核侧取得实际 `pid_tid`，用于过滤后续 syscall tracepoint。**不会把可能处于 PID namespace 内的 Python 子进程 PID 直接当作内核 TGID。**核心函数照常按指令挂接探针。

每次 pread 保存 fd、目标缓冲区地址、请求长度、文件偏移、实际返回值，以及成功返回的实际字节。读取进入、读取返回、机器指令和工作负载边界共用一个单线程观测序号；缺失、重复、未配对或越界事件不能被补齐后当作成功。

`read_boundaries.py` 为每个缓冲区字节维护最后一次成功写入它的读取实例。计算入口按地址取得字段的字节版本，要求贡献字段的完整 4 字节来自同一连续返回范围，并核对其值与实际机器入口内存一致，再把操作节点、返回范围节点接到已有的机器读取节点。

输出新增：

- `read_operations`：包括成功、失败及 EOF 的实际读取尝试。
- `external_sources`：每个最终输出实际贡献的读取实例、文件身份和字节区间。
- `dependency_graph` 的 `read-result` 边：将外部读取接到内部加工/调用传播图。

失败和 EOF 不写入任何新字节版本，因此保留此前成功读取的来源。同一地址重新读取，即使文件、偏移和值完全相同，也建立新的操作实例。部分读取若导致贡献字段缺失字节或跨多个版本，明确拒绝，不把整字段归给最近一次短读。

## 场景和真值

程序创建两个临时只读输入文件 `a.bin`、`b.bin`，内容完全相同，各有两个 uint32 值。两个偏移轮次、九类场景，共 **18 次计算入口调用、34 次 pread 尝试**。正常退出清理本次文件；临时目录使用 `TMPDIR`，未设置时在当前工作目录创建 `tracefusion-read-*`。

| 场景 | 检查内容 |
| --- | --- |
| A/B 同值，选择 A 并加工 | 来源是本次 A 读取 |
| A/B 同值，选择 B | 来源是本次 B 读取 |
| A 经 XOR/加法后与 B 合并 | 两次读取都贡献输出，保留 helper 返回依赖 |
| 同一缓冲区先读 A 再读 B | 最终只归给 B |
| 同一文件换偏移再次读取 | 区分读取操作与文件偏移 |
| 成功后再以无效 fd 读取 | 失败不覆盖旧来源 |
| 成功后再读到 EOF | 零字节返回不覆盖旧来源 |
| 无效 fd 后输出常量 | 没有外部数据来源 |
| 同一文件同一偏移重复读同值 | 来源归给后一次读取 |

主程序的 JSON 是独立的测试真值，只由评分器读取。静态分析和来源绑定不读取真值。评分包括原有输出值/输入字段来源，以及读取实例 ID、文件名、偏移/长度组成的来源集合，还检查每次计算前的读取尝试数。两文件在夹具中名称唯一；device/inode 由采集快照核验，不声称覆盖任意文件重命名或历史版本。

## 本地证据与回归

新增 10 项读取测试及 1 项采集器测试通过：C 实际编译并原生运行产生真值；独立 Python `os.pread` 读取实际文件，Unicorn 执行编译后的目标计算函数，两者形成测试事件流。**这不是 eBPF 采集，也没有把模拟的传输或 `/proc` 测试目录当作真实挂接证据。**

测试覆盖同值异源、合并、重复覆盖、读取次数及偏移变化、EBADF、EOF、常量回退；并确认缺失/重复记录、错误读取配对、未知 fd、内存快照错误、计算前值改变、短读混合版本、描述符生命周期事件、线程变化、读取与计算重叠以及报告提交失败都不能通过。采集器测试验证可选初始化发生在恢复进程之前，额外字节数组能原样保存。

完整套件 124 项：117 项通过，4 项因缺少 Go 编译器跳过，3 项既有 HTTP 测试因当前执行环境禁止 socket 而报错。当前环境也无法进行 BCC 真实挂接。旧八个完整主机包共 **4062 条事件、148 次根调用**，从实际 ELF 重新生成计划并重放完整推断/评分，均保持一致，见 [回归记录](read-provenance-regression-20261003.json)。

## 边界与后续

- 当前只支持 Linux amd64 的 pread64，单次最多 32 字节、最终绑定连续 uint32 字段。接口参数以 [Linux 6.18 的 pread64 实现](https://github.com/torvalds/linux/blob/v6.18/fs/read_write.c) 为依据；实际 tracepoint/BCC 兼容性待运行。
- 文件预先打开、内容不变；输入缓冲区在初始化后只由被观测的 pread 写入，计算期间只读。**这是受控工作负载的合同，不是已经证明任意程序都满足的性质。**尤其不能识别观测范围外一次写入相同数值的操作，也不覆盖其他进程修改文件。
- scope 内出现 close/dup2/dup3 时拒绝，防止把复用描述符认成旧文件。其他读取 API、一般句柄生命周期、并发线程和库内部传播不在范围内。
- 仍然保留既有固定布局、有限指令和栈窗口限制。不支持在计算根函数内部读文件，也未把任意系统调用自动变成传播摘要。
- 未连接数据库读取、网络发送或跨服务，也未测量完整图边准确率或性能开销。下一阶段在 C 真实采集通过后，再接入 Go 的读取边界。
