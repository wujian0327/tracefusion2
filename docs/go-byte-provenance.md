# Go 自定义字节加工：从指令推导依赖

这个独立实验验证：不给 `transform` 手写输入输出依赖摘要，能否通过编译后的指令和真实执行观测，恢复每个输出字节来自哪次读取、哪个输入字节。原有 `go-string-provenance` 场景保留。

## 运行

与此前环境一致：Linux amd64、Go 1.25.4/1.25.5、能导入 BCC 的系统 Python。无需 Docker。

```bash
cd ~/tracefusion2
git pull --ff-only
sudo env "PATH=$PATH" /usr/bin/python3 scripts/go_byte_provenance.py run
```

如需指定 Go，在 `sudo env` 后加入 `TRACEFUSION_GO=/usr/local/go/bin/go`。运行结束或失败时都会打印 `Return this archive: ...zip`，请返回该 ZIP。默认产物在 `artifacts/go-byte-provenance-<时间>/`。仅编译和规划可运行：

```bash
python3 scripts/go_byte_provenance.py build
```

## 实验设计

三次文件读取 A、B、C 都返回独立的四字节数组，内容均为 `SAME`。请求只决定使用 A 或 C；B 是未参与输出的对照。此次聚焦加工函数本身，不再将 B 作为前缀拼接。输入和输出是不同缓冲区，最终 JSON 为 `{"result":"..."}`。

两个目标使用相同的 `main.go` 和 ABI，仅改变 `transform` 的函数体：

```go
// forward.go
for i := 0; i < len(dst); i++ {
    dst[i] = src[i] ^ 0x20
}

// reverse.go
for i := 0; i < len(dst); i++ {
    dst[i] = src[len(src)-1-i] ^ 0x20
}
```

| 用例 | 选择的读取 | 输出 | 输出 0、1、2、3 对应的输入字节 |
| --- | --- | --- | --- |
| `forward_a` | A | `same` | 0、1、2、3 |
| `forward_c` | C | `same` | 0、1、2、3 |
| `reverse_a` | A | `emas` | 3、2、1、0 |
| `reverse_c` | C | `emas` | 3、2、1、0 |

以上是独立评估真值。规划器只接收二进制；推断器只接收计划与观测事件，不接收请求选择、用例名、正序/反序标签或预期索引映射。真值在各用例推断结果保存后才进入评分。

## 如何实现

1. `go_byte_adapter.py` 解析 `go tool objdump` 输出，验证每条指令的 ELF 文件字节，生成规范化指令和函数内控制流。它配置读取、加工调用、JSON 调用的边界和 Go 参数寄存器，但不配置加工依赖。
2. `byte_capture.py` 在加工函数的每条静态指令前挂 uprobe，循环每次执行都产生新事件。每条事件记录通用寄存器；字节加载及 TEST 的内存读还采集实际地址和一个字节。调用边界另采集输入、初始输出、最终输出及 JSON 字节。
3. `byte_provenance.py` 按事件顺序回放规范化指令。比较实际寄存器与预测状态，检查加载字节，计算分支后应到达的位置，逐次建立读、算术、写的定义与依赖边。它不通过输出与输入数值相等来匹配来源，也不把整个函数视为已知复制或变换。
4. 每次执行拥有独立的步骤编号，存储更新相应输出字节的定义。从最终 JSON 输出反向遍历数据依赖，得到来源集合及 `byte_sources`。反序版本的地址运算也由同一解释器执行，输入下标不是预置映射。

复用了现有整数核心的 `Sym`、`flags_for`、`branch_taken` 和共用 `backward_nodes`；32 位字段解释器本身没有被宣称已支持任意字节程序。新字节解释器接收规范化指令和 ABI 配置，Go 反汇编语法、寄存器约定及事件编码位于适配层。

采集的进程生命周期、PID namespace 过滤、perf 接收及丢失检查复用 `string_capture.collect`，通过可选 transport 参数使用另一种事件布局。默认字符串采集路径保持原接口。

## 验证结果怎么看

- `forward/plan.json`、`reverse/plan.json`：实际二进制的指令、控制流、探针位置、ABI 和哈希。
- `<用例>/events.json`：原始寄存器、内存快照和采集统计。
- `<用例>/inference.json`：逐次指令执行、加工依赖图、贡献来源及逐字节来源。
- `evaluation.json`：四次执行的来源、排除项、输出和逐字节映射与真值的比较，以及负向检查。

`byte_origin_relations` 按 `(输出字节, 来源实例, 输入字节)` 统计 TP/FP/FN、precision/recall。它是这四次受控执行中的字节来源评分，不能当作任意 Go 程序的正确率，也没有给每条指令依赖边建立独立真值。

六个证据破坏检查分别模拟采集丢失、缺少指令、错误寄存器、错误加载字节、未绑定输入和错误 JSON，均应返回 `unknown`。它们不等于对任意隐藏写入的完备检测证明。

在本地 Go 1.25.4 构建中，正序函数有 11 条静态指令，执行 37 步；反序函数有 15 条静态指令，执行 53 步。加上各 10 条边界事件，预期每个正序用例 47 条事件，每个反序用例 63 条，四个用例合计 220 条。具体二进制以计划和执行验证为准，不能只凭事件数量认定成功。

## 范围与当前状态

当前配置依然包括入口函数、四字节区域、source/sink 边界、Go ABI 和受限 x86 指令语义。消除的是 `transform` 的函数级依赖摘要，不是所有配置。

支持本次编译出现的字节零扩展加载、字节存储、32/64 位寄存器移动、异或、地址运算、加减、递增、比较、TEST、条件/无条件跳转、NOP 和 RET。未知指令、间接跳转、函数内调用、输出区外写入、区域重叠及执行超限均拒绝。当前每次最多 256 条加工指令。

仍限定一个请求/进程/goroutine，固定四字节、独立输入输出区域和无调用的加工函数。不支持一般别名、原地更新、任意位级精确依赖、任意库函数或跨服务。本实验仅重建显式数据依赖，不把请求选择和循环判断的控制依赖加入来源。线程未被固定，但本次尚无主机事件证明真实线程迁移。

读取返回数组、JSON 输出使用配置的边界模型；文件内部读取过程、JSON 库内部指令均未完整追踪。自身包禁用内联，保留符号，固定支持的 Go 版本。加工函数当前采用逐指令密集观测，尚未实现减少探针的观测选择算法，也未评估运行开销。

提交前本地已完成两种目标编译与四个用例直接执行、六项新增测试及十五项原字符串测试；最新字符串主机包的 148 条事件回放与原报告一致。新增测试使用与解释器独立构造的事件和已编译指令样本；它们不是新目标的真实 eBPF 采集。较广的历史测试集受本地缺失 Unicorn 影响，有跳过及旧测试模块导入失败，未声称全仓库测试通过。

当前本地环境没有 BCC，新目标的内核编译、逐指令挂载、实际寄存器/加载观测及端到端归因仍等待主机验证。
