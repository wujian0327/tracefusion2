# 循环内首次读取独立输入：自动补采

本轮区分两种情形：控制字节按已知规则翻转时，初值足以向前重建；每轮首次读取一个独立控制字节时，首字节不足以决定后续来源。

仍使用两个 Gin 服务、OTel、四字节输出和内容相同的 `SAME` 数据源。下游执行：

```go
func transform(dst, src, other *[4]byte, control *[4]byte) {
    for i := 0; i < 4; i++ {
        if control[i] == 0 { dst[i] = src[i] } else { dst[i] = other[i] }
    }
}
```

`control` 来自请求的四个二进制数字，在进入循环前已经到达，循环执行期间由请求私有持有且不再修改。这里的“新输入”是**对重建器而言尚未观测、不能从已观测字节推导的输入**，不是循环中再次发起 I/O。本轮不声称已支持任意调用返回值或共享内存竞争。

驱动使用 `0000、0100、0010、0110、1001、1101、1011、1111`。例如 `0000` 与 `0110` 的首尾控制字节相同，输出值也相同，但中间两个输出字节的来源不同。核心仅接收二进制计划、实际事件和既有数据边界；请求模式表仅用于评价。

## 运行

```bash
cd ~/tracefusion2
git pull --ff-only
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 scripts/gin_choice_provenance.py run --variant inputs
```

返回最后打印的 `artifacts/gin-inputs-provenance-*.zip`，失败也返回。Go、BCC 和权限要求与上轮相同。`--variant toggle` 和默认稳定控制字节场景仍保留。

| 组别 | 上游计划 | 下游计划 | 预期 |
| --- | --- | --- | --- |
| full | 完整采集 | 完整采集 | 八请求逐字节来源正确 |
| boundary | 仅边界 | 仅边界 | 当前前向重建器返回 unknown |
| auto | 自动选 boundary | 自动选 selective | 与 full 的跨服务逐字节来源完全一致 |

旧 `entry` 和 `entry_replay` 都只处理一个控制字节，必须拒绝这个四字节区域；原因记录在 `entry-rejections.json`。自动选择记录在 `build/*/observation-decision.json`。

## 观测选择与重建

1. 配置声明第四参数为请求私有的四字节控制区域，没有配置每轮应选择哪个来源。
2. 二进制 CFG 分析定位来自控制区域的可达读取，检查探针快照约定，拒绝未支持的调用、未知输入和控制区域写入。
3. 单字节入口证书不适用，因此选择器保留控制读取。实际执行时验证索引、有效地址、区域完整区间互不重叠，以及同一不可变控制字节的重复观测一致性。
4. 其他受支持指令仍由共用 ByteMachine 重放。每请求状态独立，沿用 process/G/请求代次隔离和 OTel 拼接。

固定工具链实际生成了两个控制读取位置：`TESTB AL, 0(DI)` 空指针检查，以及 `MOVZX 0(DI)(DX*1), SI` 索引读取。当前都保留，所以每请求预期有 **8 条内部事件、2 个内部探针位置**，包含四次重复的首字节检查。没有声称只采了四个必要字节，也没有实现死标志位消除或全局最小探针选择。

Go objdump 将机器码 `40 84 f6` 显示成 `TESTL SI, SI`，实际是八位 `TEST SIL,SIL`；适配器根据 TEST 的机器码确定宽度。该解析修正也有独立回归测试。

`instruction_steps[].runtime_input_evidence` 记录 `observed-control-byte`、输入区域偏移、观测值和事件序号，区分实际读取与推导状态。控制值帮助确定实际执行分支；输出来源图仍是显式数据依赖，不将控制字段混同为输出的数据来源。

## 验证与结论范围

本地验证包括全部 16 种二进制控制组合、独立执行轨迹与来源真值、同首尾不同中间输入、请求交错与线程变化、逐个删除控制事件、错误指针、范围越界、区域部分重叠和不可变输入矛盾。主机评价另外删除中间轮次的一条新输入事件，要求返回 unknown，不能用初值猜测。

真实两服务 HTTP/OTel 测试把本地数据临时设为 `LOCL`，核对按控制数组逐字节选择的响应；正式 BPF 实验仍全部使用 `SAME`。上轮主机归档的四模式原始事件重新重建后，报告与来源图不变。本轮 BPF 的实际事件数和丢失检查待主机运行，不能把本地模拟轨迹称为真实采集。

**本轮只是验证自动选择器从单字节入口复用退回到逐次读取观测的正确性。**由于数组在入口已存在，另一种可行方案是在入口一次采集整个四字节数组；本轮没有实现或比较它，所以不能据此证明循环内探针必不可少。要研究时间上后来才产生的新输入，还需扩展调用/返回或同步边界模型。
