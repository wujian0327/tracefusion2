# 新对象中的 Units 字段：条件选择与赋值来源

这是**受控变体**，不是 Online Boutique 原有订单行为，也不是已知安全漏洞复现。原有 checkout Item/Cost 实验保持独立，业务源码不修改。

## 问题与场景

测试夹具通过原始 `checkoutService.convertCurrency` 向本机 mock Currency gRPC 服务请求两次转换，得到两个不同的活 `Money` 对象 A、B。随后调用受控函数 `chooseUnits`：

```go
out := &pb.Money{CurrencyCode: "EUR"}
units := a.Units
if useB {
    units = b.Units
}
out.Units = units
return out
```

四个场景分别为相同金额选择 A/B、不同金额选择 A/B。相同金额均为 14，不同金额为 14 和 38。输出始终是第三个新对象。

问题是最终 `out.Units` 来自哪个输入对象的 `Units` 字段。不会因为最终输出值等于 14，就猜测来源是 A 或 B；也不能用输出对象地址与输入对象地址相等来解决。

## 实现与规则

1. **编译与布局**：正常优化的 Go 1.25.4、Linux amd64 非 PIE 测试 ELF。原始上游提交仍固定为 v0.10.4。从目标 DWARF 读取 `Money.Units` 的实际偏移和宽度。函数值调用保留独立目标函数，没有 `//go:noinline` 或关闭优化的编译选项。
2. **指令分析**：`scripts/bounded_field_flow.py` 从汇编识别控制流、寄存器复制、栈保存/恢复、字段读取和最终字段写入，枚举有限的无环路径。字段源参数的 ABI 是显式配置的，但“哪个输入流向最终写入”由指令数据流推导。
3. **内存与调用边界**：仅信任固定 Go `runtime.newobject` 的调用约定、调用者保存区保留、以及为配置对象布局返回新堆对象的契约。只有能证明写入基址来自该新分配的对象时，才把它与栈保存区区分开。此契约不是新完成的 runtime 二进制正确性证明。
4. **选择控制观测**：对每条路径 p，记录其最终来源字段和分支序列。所保留分支集合 B 必须满足：任何两条路径在 B 上的观测序列相同，则其来源字段相同。用确定顺序逐个尝试删除分支，只保留仍需用于区分来源的分支。
5. **运行观测**：入口采集两个输入对象和字段值；所选条件跳转处采集 x86 RFLAGS 的 ZF；返回处采集新对象和输出字段值。推断只读二进制计划和这些事件，不读取 fixture 的 `useB`、场景名或独立真值。

本地实际编译结果：两个静态来源路径，一个有区分作用的 `JE`，因而为**入口 + 条件跳转 + 返回，共三个探针位置**。`JE` 是否跳转与 A/B 的对应关系来自指令路径分析，不硬编码成“true 就是 B”。

例如，B 路径先读 A，再读 B；分析器沿最终存储的值依赖确定 B 覆盖了 A。一个额外但不流入最终存储的读取不会被误当成来源。测试中将输入寄存器保存位置调换后，静态来源映射也随之改变。

该选择只是有限路径模型中的贪心删除结果；不是全程序最优采集，也不宣称所有 `if` 只看条件就能解决。

## 两组主机验证

| 组 | 本地位置数 | 应有结果 |
|---|---:|---|
| selected | 3 | 根据所选分支方向找到本次执行的实际字段来源 |
| boundaries | 2 | 没有分支证据，保留 A/B 两个候选 |

两组各跑四个场景，共八次采集。`boundaries` 的歧义是预期结果；它与单纯“采集失败”不同。此基线故意不使用数值相等消除候选，即使金额不同也保留静态候选，不代表所有可能的边界分析算法都只能如此。

来源值仅用于一致性检查：若已选择的来源值与最终输出不符，则返回未知，不继续报告确定来源。缺失必要分支事件也不能得到确定归因。采集丢失、读取失败、调用身份不一致使运行失败。

## 运行

在 tracefusion2 仓库根目录运行；沿用之前的 Linux/WSL2 BCC 环境与 Go 1.25.4，不需要 Docker：

```bash
git pull --ff-only
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 experiments/checkout-field-choice/run.py run
```

支持 `--go /path/to/go`、`--checkout /path/to/microservices-demo` 和 `--output`。结束或失败打印 `checkout-field-choice-时间.zip` 路径，请返回该归档。

归档包含 `function.asm`、`field-flow.json`（路径、实际来源读取、最终写入、所选分支及前提）、两组计划、内核事件、推断与独立真值。

只检查本地编译和夹具：


## 验证边界

- 本地正常编译、ELF 指令/DWARF 布局检查和四个原生场景已通过。17 项单元测试覆盖动态分支、同值来源、覆盖、无效读取、缺失证据、错误标志位被真值检出、未知调用/加工拒绝、64/68 字节 perf 布局等。
- **原始 choice 变体已通过主机 BPF 验证**：`checkout-field-choice-20261009-023504-014180.zip` 的八次采集、20 个事件，经离线重算与独立真值核对全部通过；二进制哈希和 33 条汇编指令也核对一致。相同值两组分别正确指向 A/B。overwrite 变体的独立主机结果见下文。
- 来源仅追到本函数输入的 `Money.Units` 字段；不声称已还原 Currency 服务内部数值计算、网络字段映射或数据库来源。
- 输入对象在一次调用期间保持存活且不被并发修改。支持同一输出字段的多次完整复制写入，以最终写入为准；当前不支持循环、多个查询字段、部分字段覆盖、一般算术、未知调用、复杂内存别名、SIMD/条件移动等未建模指令。遇到这些模式拒绝生成计划，不能默认为传播未变化。
- 最多枚举 32 条无环路径；未做条件可满足性求解，静态路径可能保守包含不可行路径。边界观测和路径匹配仍必须满足采集完整性与单次调用的前提。
- 字段 ABI、布局类型和目标函数入口仍配置；指令层的字段复制依赖与区分分支是新增自动推导部分。全程不把独立真值写进观测计划。


## 新增：覆盖后自动省略无关分支

运行同目录的第二个变体：

```bash
git pull --ff-only
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 experiments/checkout-field-choice/run.py run --variant overwrite
```

`overwriteUnits` 是新增测试代码，不是上游 checkout 原始逻辑。它首先写 A，按第一个条件可能改写为 B，然后按第二个条件**无条件覆盖为 A 或 B**：

```go
out.Units = a.Units
if firstB { out.Units = b.Units }
if finalB { out.Units = b.Units } else { out.Units = a.Units }
```

目标仍是返回时 `out.Units` 的实际输入字段来源。共享分析核心为同一新对象的完整字段写入建立有序定义：后一次完整写入替换前一次来源。每条静态路径在 `writes` 中保留全部写入，`sink` 指向最后一次写入。未知写入、部分覆盖和不明别名仍拒绝分析，不能因后续覆盖而直接忽略风险。

在正常优化的 Go 1.25.4 二进制中，已确认两个条件分支、四条静态路径、每条路径两次或三次实际字段写入。分析器自动保留第二个分支，省去第一个分支。若编译器消除了早期写入或改变了该结构，runner 会明确失败，避免把编译器删除代码误报为观测选择的效果。

| 策略 | 探针位置 | 单次预期事件 | 预期结果 |
|---|---:|---:|---|
| all_branches | 入口、两个条件分支、返回 | 4 | 最终来源精确 |
| selected | 入口、必要的第二个分支、返回 | 3 | 与 all_branches 相同的最终来源 |
| boundaries | 入口、返回 | 2 | A/B 两个候选 |

场景覆盖两个条件的全部四种组合（aa/ab/ba/bb），各有输入相同值与不同值两组，共八个场景、24 次 BPF 采集。名称首字母为早期选择，第二字母为最终选择；真值仅由测试夹具记录，推断不读取这些名称、条件参数或真值文件。固定编译配置下共预期 72 个事件；实际采集必须以主机结果为准。

**省略早期分支只对“返回字段的最终来源”成立。** 若要回答每次中间赋值的实际历史，就不能使用该省略后的观测集。计划中保留的静态中间写入路径不等于已观测到的动态历史。位置/事件从 4 减到 3，也不能直接宣称 CPU 开销降低 25%。

本地已通过：真实优化 ELF 分析、DWARF 布局校验、八个原生场景、17 项单元测试；原始 choice 四个原生场景也回归通过。单元测试额外检查：去掉一个分支臂上的最终覆盖后，早期分支重新变成必要观测；只采已被覆盖的早期分支无法确定最终来源；被覆盖前的未知/部分写入仍拒绝。**overwrite 已通过独立主机验证**：`checkout-field-overwrite-20261009-025731-295542.zip` 的 24 次采集、72 个事件经重放全部符合预期；selected / all_branches 各八次精确归因，boundaries 八次保留歧义。校验了 ELF、48 条汇编指令、重新推导的静态路径以及 24 份采集程序；无丢事件、读取或提交错误。该结果仅覆盖上述受控变体。
