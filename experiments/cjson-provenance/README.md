## 来源语义与公平性

拟定来源标识是 `(用例, 输入字段路径, 写入版本)`，不是值；
独立语法扫描器按结构记录每个输入字符串值 token 的半开字节区间，另用 Python JSON 解析交叉核对。
调用方显式替换的数据是独立的 `replacement` 来源，即使值与旧字段相同也不能合并身份。
输入键名、容器符号、数组索引与路径请求作为选择/地址信息单列，不能混入内容来源。
目标拟绑定原始 cJSON 节点的 `valuestring` 内容，不能靠值匹配输入。

最初 `cases.py` 保存的是**格式字段来源预期与业务值真值**，不是逐指令显式依赖真值。
后续独立的 `field_truth.py` 按以下原始源码行为增加字段级显式依赖标注，见字段结果；逐字节真值仍未建立。
在实际原版 `parse_string` 中，普通字符直接复制，`\"`、`\\`、`\/` 复制转义后的输入字符；
`\n`、`\t` 等则由分支选择常量赋值。后者即使在格式语义上来自输入字段，显式数据污点也可能为空。
Unicode 还涉及查值、算术、掩码和分支，须分别定义并校准字节传播规则。
因此转义用例先保留为语义诊断，不拿格式来源集合直接评判 libdft64 是否漏报。
空字符串有对象/字段身份，但内容长度为零；无目标和未知也不能混为一类。

未来精度表要明确分母、未知与无目标：20 个已存在字符串目标和 2 个无目标检查分列。
任何不支持项都保留，不能运行后删掉难例再宣称全覆盖。后续主机实验已有 18 个解析阶段查询完成双核心还原；2 个替换后的目标仍在该阶段范围外。
字段存在性诊断与逐字节独立准确率分开，后者尚未建立。

## 已发现的实际接入缺口

对覆盖率构建到达的函数，在普通 ELF 中审查其完整函数体，当前离线 `replay.py` 拒绝了
132 个静态指令位置。**这是静态过近似，不是 132 条实际执行失败记录，也不是未知查询数。**

- 字节读写、`movzx` / `movsxd`、RIP 相对 LEA 与部分地址形式。
- `setcc`、条件移动、带进位/借位运算、位测试、移位。
- 原始对象初始化等路径中的 XMM/SIMD 操作。
- 本次工具链构建的段寻址/栈保护行为。
- 分配器间接调用及字符串/内存库调用；仅在分派器中接受 CALL 不等于已正确处理被调函数。

现有 27 回调适配器在受控 C 上的校准仍然有效，但不能外推为对 cJSON 的支持。
本次没有修改该已校准核心，也没有禁用上述行为或替换 cJSON 业务来制造通过结果。
后续已增加独立的 `parser_core.py`，限定在分配后的字符串解码区间，原样提取 46 个回调；
它并不消除整个 cJSON 的全部 132 个静态审查位置，新增能力已完成 18 个查询的主机校准，但只覆盖实际执行到的指令形式。
构建固定 `-O1 -g -fno-inline -fno-lto -fno-ipa-icf -fcf-protection=none`，
最后一项沿用先前诊断构建的配置，不代表任意编译选项。

下一步实施顺序：

1. 审核已建立的字段级显式依赖标注与评分；逐字节核验作为底层检查，不再作为全部真实场景的前置条件。
2. 保留 22 个请求的全部状态；替换和序列化若扩展，单独定义契约并校准新增执行路径。
3. 后续再接入另一种语言的真实对象；当前诊断日志不作为性能测量。

`driver.c` 内的 `tf_cjson_begin` / `tf_cjson_sink` 只暴露输入、原对象指针和请求序号，不计算来源。
`parser_capture.cpp` 已连接这些锚点；本轮原生执行记录已逐步复核，详见主机结果。

## 复现当前阶段

需要 Linux amd64、GCC/gcov、Git、Python 和下面的 Python 依赖；首次运行按固定 tag 检出并核对完整提交。
默认生成新输出目录，输出保留源码、普通/覆盖率 ELF、原生输出、独立真值、gcov 记录、指令审查及命令。

```bash
git switch perf/payment-steady-state
git pull --ff-only origin perf/payment-steady-state
.venv-libdft-offline/bin/python -m pip install -r experiments/cjson-provenance/requirements.txt
.venv-libdft-offline/bin/python experiments/cjson-provenance/preflight.py
```

可用 `--source /path/to/cJSON` 指定已检出的固定版本，`--output` 指定不存在的新目录。
**本地已完成本轮原生检查，用户无需重复执行；以上命令仅供复现，不会运行 Pin 或溯源比较。**
