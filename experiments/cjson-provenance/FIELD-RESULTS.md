# cJSON RQ1：字段级显式来源关系

2026-10-12。使用已核验的同一主机结果包，未重新采集、未增加用例、未修改两个还原器。
新增独立于两个传播实现的源码规则标注，并将已有字节标签投影为字段身份后评分。
**在预先限定的 18 个解析目标上，我们与原版 libdft64 均达到字段关系 Precision/Recall 100%。**
该结论有范围限制，也尚未经过第二位研究者人工复核；不能据此声称全库、逐字节或任意输入的准确率。

## 评分单位与真值

关系为 `(本次执行的源字段实例, 本次执行的目标字段实例)`。
源标识包括用例、输入/替换边界、写入版本和 JSON Pointer 路径；目标由本次运行的节点与输出指针绑定，
不同运行间使用用例和查询路径对齐。不按相同值匹配，也不按数组中相同字符串合并。
字段内容只计显式数据依赖，控制选择、地址计算、对象身份、字符串长度和结尾 NUL 不混入内容来源。

`field_truth.py` 显式列出全部 22 个请求及依据，不从工具预测标签生成答案：

| 原始源码行为 | 字段级预期 |
| --- | --- |
| 普通字符直接复制 | 当前输入值字段 |
| 引号、反斜杠、斜线转义 | 复制转义后的字符，来源仍是当前输入值字段 |
| Unicode / 代理对解码 | 十六进制字符参与码点运算和 UTF-8 编码，来源是当前输入值字段 |
| 空字符串 | 空内容来源集合；字段对象存在 |
| 换行、制表符转义 | 原始分支写入常量；显式内容来源集合为空，控制影响另论 |
| 解析后替换的 payer | 来源应为 replacement v1；当前解码适配器范围外，不评分为成功 |
| 缺失字段 / 不完整 JSON | 无目标，独立列出 |

固定依据为原版 `cJSON.c` 中的 `parse_string`、`parse_hex4`、`utf16_literal_to_utf8` 和原生驱动；
源码 SHA-256 为 `298581a04a36c0165da4b0aade235c23088cb2faa58651d720ea2f3706ed0b0d`。
这是**在结果已可见后进行的、依据源码的非盲标注**；“独立”指预期不由任一传播引擎产生，
不意味着已有多人独立人工审查。正式论文定稿前应由另一位研究者审核这些标注与实际执行依据。

预测投影使用输入中所有值字段的独立语法区间：字节标签落入哪个字段，就归到哪个字段。
落入其他字段会产生错误关系；落入键名、语法符号或 NUL 的来源会保留为额外来源，不能直接过滤。
这允许发现同值不同来源的混淆。投影会合并同一字段中的字节，因而不能发现该字段内部字节级的多报或漏报。
字段真值也不表示业务格式来源、隐式信息流或反事实最小依赖。

## 分母与结果

| 状态 | 数量 |
| --- | ---: |
| 全部固定请求 | 22 |
| 已存在字符串目标 | 20 |
| 本阶段评分目标 | 18 |
| 其中非空来源集合 / 空来源集合 | 16 / 2 |
| 范围外替换后目标 | 2 |
| 原生无目标检查 | 2 |
| 已存在目标的评分覆盖比例 | 18/20 = 90% |

| 方法 | TP | FP | FN | Precision | Recall | 来源集合完全匹配 | 范围内 unknown |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 我们的还原 | 16 | 0 | 0 | 100% | 100% | 18/18 | 0 |
| 原版 libdft64 | 16 | 0 | 0 | 100% | 100% | 18/18 | 0 |
| 提取的 libdft64 核心（校准项） | 16 | 0 | 0 | 100% | 100% | 18/18 | 0 |

原版与提取核心属于同一个算法，最后一行只说明适配一致性，不能算成第二个独立外部对照。
无目标检查来自共享的原生执行及对象绑定验证，不增加任何方法的 TP，也不冒充三个引擎分别完成的解码查询。

每条查询的 TP/FP/FN 分别是预测集合与真值集合的交集、额外项、缺失项数量，再按方法求和计算微平均：
Precision = TP/(TP+FP)，Recall = TP/(TP+FN)。集合完全匹配要求既无额外项也无缺失项。
空来源查询不增加 TP，但预测出来源会增加 FP。unknown 不算空集合、不算完全正确；范围内已知真值关系仍计为未恢复。
若某项分母为零，指标返回 null，不能自动写为 100%。本轮没有范围内 unknown。

全部精度指标限定于预先声明的 18 个解码目标，不能写成 22/22 请求支持或整个 cJSON 支持。
本轮双方一致，没有准确率优势；所有 16 个非空来源查询各有一个源字段，尚不能证明多来源合并准确性。
来源边界仍在分配成功之后，不支持此前解析控制路径、分配器、替换和序列化的完整传播。

```bash
python3 experiments/cjson-provenance/score_fields.py \
  --archive artifacts/cjson-parser-host-20261012-041303-736089.zip \
  --output artifacts/cjson-field-scoring-new
```

`--archive` 可换成实际保存的 ZIP 路径；`--output` 须是不存在的新目录。

这些只是评分实现检查，不作为新增业务实验或准确率样本。
