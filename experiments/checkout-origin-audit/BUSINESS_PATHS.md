# 原始 checkout 业务路径核查（2026-10-09）

## 结论与下一步

同一个 Online Boutique 项目可以继续使用，但不能把新增 `chooseUnits` / `overwriteUnits` 函数说成上游已有业务行为。本次编译的是没有加入任何测试夹具的原始 checkout 可执行文件，检查了六个业务函数的汇编并逐条核对 ELF 指令字节。

下一步建议接入 **原始 `money.Sum` 的返回字段来源**，以它作为支付金额路径中的第一个真实计算环节。先限定单次成功调用、两个输入金额、返回的 `Units` / `Nanos`，再讨论循环累加与 `chargeCard` 的衔接。此次没有实现该接入，也没有声称已完成原始业务的动态字段溯源。

## 实际已有的路径

上游固定提交：`474d0f2eb73d97525234995a40d7781b7923a07d`（v0.10.4）。下表为源码人工核查；附带 JSON 是二进制清单，不是自动生成的血缘证明。

| 原始业务路径 | 输出与实际来源 | 当前已有证据 | 尚缺支持 |
|---|---|---|---|
| `prepOrderItems` → `OrderItem.Item/Cost` | Item 是对应购物车对象；Cost 是本轮换汇返回对象 | 之前主机实验验证了限定场景中的对象引用对应关系 | 引用身份不能直接替代字段值的写入历史；本函数包含循环、RPC 调用、写屏障 |

**没有在上述被检查的原始逻辑中找到与 `overwriteUnits` 完全相同的“先选 A/B、后续无条件覆盖”的业务模式。** 不应人为把这种模式植入业务，然后将它包装为自然存在的真实案例。

`OrderResult` 并不包含计算后的支付总额；该总额传给 `chargeCard`，随后进入 `ChargeRequest.Amount`。如果未来以总额为溯源终点，应明确这是出站支付请求字段，不是声称它是 checkout 响应里的总额字段。

## 为什么选择原始 Sum，而非立刻扩大到完整订单

`money.Sum` 是实际支付路径调用的代码，输入输出范围清晰，又包含真实的数据加工。源码先计算 `units=l.Units+r.Units` 和 `nanos=l.Nanos+r.Nanos`，随后依据符号与范围执行进位或校正。

这使来源表示必须从“单一输入字段”扩展为“输入字段集合”。例如进位路径中的返回 `Units` 还使用了 `Nanos` 的计算结果，不能始终只标注两个输入的 `Units`。

必须先区分两种问题：

- 数据依赖：本次实际执行的算术和复制指令读取了哪些来源字段。
- 控制依赖：哪些字段决定走哪个分支、调用是否成功。

字段只影响条件而没有进入某个分支的算术，不应在没有明确语义定义时与直接数据依赖混为一谈。反之，某个输入恰好为零也不自动意味着它没有被读取或没有数据依赖。第一步应报告执行级数据依赖，并单独记录必要的路径证据；这不是反事实因果分析。

本次**尚未证明** Sum 内的某个分支可以省略，也没有提出事件下降百分比。要先从真实指令推导每条成功路径的字段来源集合，再检查哪些路径对具体查询等价。若它们的来源集合都相同，动态分支对该查询就可能没有区分收益；这也是需要如实记录的结果。

## 二进制核查与支持边界

正常优化 Go 1.25.4、Linux amd64、CGO 禁用；没有关闭优化、没有改上游源码、没有注入夹具、没有运行服务或采集 BPF。

| 函数 | 反汇编指令数 |
|---|---:|
| PlaceOrder | 565 |
| prepareOrderItemsAndShippingQuoteFromCart | 252 |
| prepOrderItems | 196 |
| convertCurrency | 73 |
| money.Sum | 181 |
| money.MultiplySlow | 127 |

指令数是完整符号文本的清单，包含错误路径与栈增长处理，不是本次执行的指令数，也不是探针数量。生产 ELF 的 checkout 主包符号是 `main.(*checkoutService)…`，与之前测试 ELF 的完整导入路径符号不同；不能直接沿用旧测试二进制的符号或偏移。

当前新核心 `bounded_field_flow.py` 只支持固定指针参数、同一新对象字段的无环完整复制。它不能直接处理此处的结构体值参数与返回、`ADDL/ADDQ` 数值加工、`IMUL/SAR` 常量除法实现、`MOVUPS` 结构体搬运，以及校验调用。这里是与该新核心的差距，不表示仓库其他较早的实验从未处理过循环或跨函数。

未来应根据真实编译结果补所需语义；不能将 `Sum` 硬编码成“所有输入都参与”、把未知指令视为无影响，或者先读取独立真值再决定来源。
