# 原版 Java 字节数组路径与来源还原

2026-10-11：已接入 Apache Commons Codec **1.17.1 发布 JAR** 的
`MurmurHash2.hash32(byte[], length, seed)` 及其同类静态调用闭包
`getLittleEndianInt(byte[], index)`。直接执行原版发布 JAR，保存的原始 class 与
JAR 内字节一致；没有提取、重写或简化业务函数。上游包含循环、按索引读取字节、
整数混合运算、内部调用和带贯穿执行的 `tableswitch`。

本轮是一个开源库计算路径，不能称为完整 Java 应用或任意字节码支持。

## 新增语义及支持边界

- 支持有界、非空引用、**只读 `byte[]`** 参数，数组长度允许为 0，最多 4096 字节。
  `BALOAD` 按 JVM 有符号字节扩展为 int；数组身份使用运行时对象身份，位置由索引区分。
  数组写入、数组创建、其他元素类型、外部调用和异常恢复仍不支持。
- 支持 `tableswitch` / `lookupswitch` 的原始偏移解码和动态目标恢复。full/sparse
  记录实际选择值，boundary 从输入和原始指令计算；不把选择条件混成直接数据来源。
- `initial_array_element` 来源声明绑定对象身份、数组索引、初始版本；同值元素不合并。
  读出的元素定义作为数据父节点，数组引用和索引定义单独作为地址父节点。
- snapshot-v3 在根调用后记录每个数组的身份、**独立长度和完整有符号字节列表**。
  长度与内容数量不符、别名快照不一致、越界来源、丢失必要证据均返回 unknown。
  同一数组跨调用复用时，后续快照必须与已记录的不可变内容一致。
- 只读契约包括观测区间内没有外部线程、native 或其他未观测代码修改源数组。
  此契约不是由边界日志自动证明的；不能声称边界重放能检测所有并发修改或一致篡改。
  Collector 仍以强引用保留对象身份，会改变对象存活期。

三组统一承担同样的完整入口快照成本。full 记录全部闭包内步骤和访问，sparse 删除
可由原始字节码推出的步骤但保留读、分支、switch、调用与返回；boundary 只记录入口
参数、完整数组快照、根返回值和生命周期信息，不含内部指令地址。
这仍是固定策略对照，没有自动最优探针或全局成本优化声明。

## 实际 JVM 正确性

20 组输入覆盖长度 0–12 的前缀、空数组、相等字节、零字节、带符号字节、不同未读
尾部、多个四字节块以及不同种子。最大实际输入 64 字节。default 和 `-Xint` 各运行
三组，共 6 次正常 JVM 采集；**20 个不同输入查询，不是 120 个独立场景**。

| 方法 | 正确查询（含两种 JVM 模式） | 原始事件 |
| --- | ---: | ---: |
| full | 40/40 | 8,656 |
| sparse | 40/40 | 958 |
| boundary | 40/40 | 126 |

三组全部返回值、来源、定义图、分支结果和别名关系一致。独立值 oracle 使用 Python
整块小端转换和打包尾部计算；没有使用解码器、图或引擎算术函数。独立来源规范是
被读取的前缀字节，加上参与初始异或的 length、seed；同时给未读尾部每个字节打标签，
检查它们没有出现在结果中。操作数依赖不是最小代数依赖或位级精确依赖，即使字节
恰好为零，也保留相应运算操作数来源。没有按结果数值相同猜来源。

独立复核重新还原 **9,740 条原始事件**。8 项离线拒绝检查通过：缺快照、快照截短、
读取值错误、同值但索引错误、缺读、错误 switch 选择值、缺返回、查询绑定更改。
null、超过 4096 字节、实际越界异常三项真实 JVM 场景均返回 unknown。

另外用 6 个针对性语义用例、三种模式进行了 **18 次 JVM 采集**，核验同值不同数组、
数组别名和 `lookupswitch` 的三个键及默认分支；全部原始日志另行重新还原。
数组写入分别被静态计划和实际 Agent 拒绝。旧 snapshot-v2 字段/嵌套调用的三组
聚焦回归通过，遗漏可达方法仍被拒绝。这些是语义检查，不计入上游程序覆盖数。

**在当前只读数组路径上，完整入口快照仍足以恢复来源。** 增加循环、字节读取和
switch 没有使内部观测成为必要条件；不能据此宣称 sparse 优于边界重放。

## 成本证据状态：未通过完整核验

已实现 native/full/sparse/boundary 的同负载入口：每轮 40 次原始哈希调用，全部
查询来源；1 个排除的准备块和 6 个正式块，顺序由种子 20261011 打乱并记录。
构建及静态计划在计时外，在线包含新 JVM、ASM 和采集，离线包含新 Python 进程、
原始 class 解码、图构建、查询和 JSON 输出。CPU 为子进程资源统计。
独立准备进程不是后续 JVM 的 JIT 预热；不作稳态吞吐或服务延迟声明。

本地两批成本归档均未通过严格复核：第一批两份业务 stdout 为空；第二批两份业务
stdout 为空、一份原始采集日志为空，另有一份离线 stdout 与归档哈希不符。第二批
只重跑成本，复用了已核验的正确性采集。没有修改缺失文件、重建伪原始输出或
把有问题的测量排除后拼成正式性能结果。具体缺陷保存在公开报告。

**此前进度消息中的性能降幅是尚未核验的初步值，已撤回。本文不报告新的有效
耗时/CPU/内存收益。** 文件缺失原因未查明，不能归因于被测库或声称 fsync 已解决。
增加了标准输出落盘操作，并把采集完成状态改为 `collected`；必须通过独立严格复核

## 证据与主机运行

原版构件：[Commons Codec 1.17.1](https://repo.maven.apache.org/maven2/commons-codec/commons-codec/1.17.1/)。
代码/源码 JAR 均固定 SHA-256，保存 Apache LICENSE/NOTICE；没有只依赖可变的最新版本。
公开记录：`array-validation-20261011.json`。正常日志复核来源：
`artifacts/java-arrays-20261011-141331-587654`，其中正确性采集复用自
`java-arrays-20261011-140944-275218`。成本目录保留缺陷，不作为有效性能证据。

```bash
git pull --ff-only origin perf/payment-steady-state

# 使用 PATH 中的完整 JDK；需 JDK 17+、Python 3.10+ 和 C 编译器
if command -v javac >/dev/null 2>&1; then
  jdk_dir="$(dirname "$(dirname "$(readlink -f "$(command -v javac)")")")"
  python3 experiments/java-collection/compare_arrays.py --jdk "$jdk_dir"
else
  echo "需要完整 JDK，或用 --jdk 指定实际安装目录"
fi

# 将此处目录替换为上一步打印的实际目录，进行完整严格复核
python3 experiments/java-collection/verify_arrays.py \
  artifacts/java-arrays-YYYYMMDD-HHMMSS-ffffff \
  --output artifacts/java-array-verification.json
```

正确性单独复核可显式加 `--correctness-only`，输出强制标记
`coverage=correctness_only, costs_qualified=false`，不检查或计入成本运行的来源结果，
并列出观察到的成本归档缺陷。**不得用这个选项代替正式性能复核**。
来源边界仍是哈希入口的数组元素和整数参数，不自动延伸到文件、网络或上游服务。
