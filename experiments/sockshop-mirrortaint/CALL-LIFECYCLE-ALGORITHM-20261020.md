# 调用生命周期修复与效果核验条件

本轮仅修复有限读取监测器的调用闭合，不扩展 Orders 保存/异步、一般循环或指令语义。原 c3e6739 的首次覆盖结果不变；新版本的回归与成本分别保存。已有模型见 [有限读取效果与 HTTP 事实](SOCKSHOP-MODEL-ALGORITHM-20261020.md)。

## 调用闭合与异常

读取效果协议 v2 为每个受监测的非构造器 invoke 发出唯一 call-id 的 enter，以及恰好一个 normal exit 或 exceptional throw。异常保护区只包住原 invoke：接收者为 null、尚未进入被调方法即失败，也有 exceptional 记录；不能由这一记录断言被调方法体已经执行。

合成 handler 优先记录异常，随后重抛同一个 Throwable。handler 位于原 invoke 所属的业务保护区内，因此重抛继续到原 catch/finally；不替换异常、不跳过清理，也不吞掉异常。正常 after 不在这个合成保护区内。插桩自身错误发 problem，使捕获无效，不能伪装成有效业务证据。

异常调用闭合后仍没有取得正常只读返回证明：记录 valid=false、调用前相关字段和异常对象，阻断相应效果。父组合调用的失败计数也受到影响。根正常退出或异常退出均发出调用总数、未配对数和完成状态的 summary，随后清理线程状态。根异常没有绑定返回，不产生答案。采集被杀、summary 丢失、调用未闭合、重复/错配或根退出状态矛盾，仍拒绝整批；本轮没有引入按请求忽略坏证据的容错。

静态候选限制、类哈希和实际虚调用实现核验、每个执行子调用的闭合及契约检查须共同成立。构造器不使用非构造器调用协议；它们依赖既有窄构造器字节码条件与写入监测。任意构造器没有获得支持。组合候选不接受异常表，因此“异常已配对”不会把含 catch 的 helper 自动升级为只读模型。

## 状态与写入覆盖

“相关字段”是计划的 response_binding.source_fields 及已选 profile 所需字段，由声明目标、复制规则、选中 getter 等确定，不是任意可达堆状态。快照沿已声明、已核验的 DTO schema 递归到字段，并遍历允许的具体 List/Map；包含对象身份、字段版本、元素位置/键及内容阶段。别名由同一个对象身份体现；循环对象、超界、未知容器实现不能得到这种快照保证。未纳入 schema 的状态不能仅靠前后比较声明安全，须由静态无写约束、完整子调用检查和明确公共模型排除其影响。

版本来自固定应用类中的受跟踪 PUTFIELD，包括活动根调用外的写入；full/selective 保持必要版本维护。允许的容器修改调用另有保护，内容快照核对补充被覆盖路径中的检查。它不是全堆写屏障：反射/native、未建模库内部写、并发共享修改及任意容器修改历史没有完整覆盖。相关版本相同只是必要检查之一，不能代替静态限制、调用闭合和库契约。

## 效果检查不创建来源

取得效果证明，只允许保留已有来源关系，不产生新的来源节点或任意返回值依赖。来源仍必须由声明入口参数、具体仓储读取返回或实际 RPC 读取，提供相同对象、字段、已观测版本与根调用坐标。List/Map 使用具体容器、位置/键和阶段；通信使用具体消息、RPC 及 JSON 路径。目标由真实返回对象与序列化路径核验，返回快照不是来源。

新增反例 `computed(input) = new Item(input.getText())` 没有修改输入；在窄构造器与子调用契约下，效果检查可以通过。但新 Item.text 的依赖没有由当前 response-forward profile 建立，因此答案仍为 unknown。即使它与输入同值，也不能把旧对象的来源复制给新对象。

## 成本口径

必要的调用生命周期/效果、身份、版本、返回绑定、序列化检查及 HTTP/JSON 字段通信证据均计入主实验。source_evidence 额外旁路原始 HTTP 字节，当前还原器不将 http-source-fact 注册为来源：它用于独立 HATEOAS 真值与诊断。新成本任务先验证该开关的答案与必要拒绝检查，再声明主配置是否关闭；关闭它不关闭 HTTP/JSON 字段证据。full/selective 的全局开关和核验规则相同。

Cart 只读转发、Train 第二次仓储读取返回绑定和原多来源票价分别测量；不合并成一个优势比例。批量答案等待包括剩余窗口、关闭采集和离线处理，不能解释成工具固有流式延迟。静态规划另计，Agent 编译和镜像启动不冒充规划算法耗时。
