# 调用配对修复后的成本协议

算法冻结：`2b3b929`。原版 JAR、固定镜像、公共契约和源码哈希见 `artifacts/call-lifecycle-revision-20261020/algorithm-freeze.json`。本轮没有扩展业务语义，不复用旧版性能数字。

依次比较三种查询任务，各自单独报告：

| 任务 | 入口与目标 | 声明来源边界 | 部署 |
| --- | --- | --- | --- |
| Cart 有限读取模型 | `ItemsController.getItems` → `/*/itemId` | 实际 Cart 仓储读取返回的对应元素字段 | 原版 Carts + Mongo |
| Train 响应绑定 | `TrainServiceImpl.retrieve` → `/data/economyClass` | 本次第二次 findById 返回的字段 | 原版 Train + Mongo |
| 票价多来源计算 | Basic travel → 两个 prices Map 条目 | 实际 Route 距离元素与 Price 费率响应 | 原版五 Java 服务 + 四 Mongo |

每个任务均测原版、full、selective，各五次独立容器/卷部署；每轮随机配置顺序，预热30秒、稳态60秒、2请求/秒、并发上限2、资源采样2秒。成本任务依次执行，不互相重叠；校准不作为性能结果。业务 JVM 各1 CPU/768 MiB、Mongo 各1 CPU/384 MiB；每个任务内部三配置保持相同 JVM 参数。新 Cart/Train 驱动采用现有 Sock Shop JVM 参数；票价沿用原票价驱动参数，任务之间不宣称同一 JVM 调优或合并比较。

full/selective 共享计划、Agent、必要观测、全局开关、事件格式和还原器，仅 service.mode 不同。full 仍是当前纳入类与根调用范围的字段/分支观测，不是整个 JVM。原版没有来源输出，来源能力记 N/A；MirrorTaint/Phosphor/FlowDist 未校准这些新任务，不加入本表。

主配置关闭额外 source_evidence 原始 HTTP 字节采集的前提：原始字节开启/关闭下，通过独立来源核对及必要证据破坏检查。HTTP/JSON 字段消息、对象版本、返回/序列化绑定和调用效果检查始终保留，全部计费。Cart/Train 任务没有需要该原始 HTTP 读取探针的下游 RPC，必须如实报告捕获事实为0；另外使用实际存在 RPC 的票价路径验证开关，不据零事实任务推断原始字节采集的一般开销。

Cart 使用六个持久购物车，经原 API 准备非空1/2项列表，同值字段和跨车相同 itemId 保留；不在计时期修改数据。Train 使用五条固定实体，保留同值字段及重复请求；真值明确选第二次读取。票价复用已冻结19个能产生目标的模板，缺失 Train 的未产目标模板留在正确性校准。真值投影不调用 TF 传播或跨服务图连接。

每次部署保存业务输出、实例来源预测和独立真值、延迟 p50/p95/p99、完成吞吐与错误率、业务 JVM/整部署 CPU与RSS、稳态/整批事件及字节、控制台字节、离线解码/核心/评分/导出阶段、子进程墙时/CPU/峰值RSS、请求完成到采集关闭及答案可用的批次等待。性能样本排除预热，来源核对包含预热与稳态并分别计数。

五轮配对比值报告每轮、其中位数及范围；不将请求当作独立部署重复，不宣称显著性或最大吞吐相同。p99 每轮约120个请求，仅作描述。计时期出现错误、unknown、来源不匹配或采样不足，则该部署不具备正式比较资格，保留失败后另行处理，不能删去失败填入成功数据。

静态规划另测五轮随机任务顺序、每次新进程、固定同一个逻辑 CPU，记录 JAR 提取、字节码建模、模型解码、计划分析和导出阶段，CPU及进程树采样RSS峰值；核对生成计划与部署计划完全相同。系统页缓存不清空，因此这是新进程重复，不是磁盘冷启动。Agent 编译、镜像准备与部署启动单列排除；full/selective 共享一份规划，无需捏造两份规划成本。
