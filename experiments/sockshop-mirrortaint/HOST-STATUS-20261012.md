## 独立执行的受控运行时探针

本次在可信、固定 SHA-256 的原版 JAR 上运行 `RuntimeScopeProbe.java`，JDK 沿用 Corretto 8。
通过公开 `TaintHeap` API 和单线程 executor 检查状态作用域；没有设置真实污点标签，
没有执行 Sock Shop 业务、字段传播或请求连接，也没有安装适配器。

| 检查 | 实测 |
| --- | --- |
| 父线程 startup 后 available | true |
| 新工作线程未 startup 时 available | false |
| 工作线程显式 startup 后 available | true |
| 父线程能否自动看到工作线程独立 heap 的 sentinel 槽 | false |
| 显式 shutdown 后复用工作线程 available | false |
| 工作线程清理后父线程 available | true |

此探针支持 ThreadLocal 状态不自动继承/合并的窄结论，不能单独证明主机日志碰撞或完整传播故障。
它说明“在 worker 调 startup”不能直接当作适配已完成：必须另外验证字段标签如何随异步结果返回。
结果、源代码摘要与原始日志见 `runtime-scope-validation-20261012.json` 和
`runtime-scope-evidence-20261012.json`。

```bash
python3 experiments/sockshop-mirrortaint/probe_runtime_scope.py \
  --agent /path/to/mirrorTaint.jar --jdk /path/to/jdk8 \
  --out artifacts/sockshop-runtime-scope-new
```

## 接下来先校准什么

1. **记录完整性**：为采集事件建立独立实例标识和完整记录通道，避免覆盖；记录丢失/重复必须可检测。
   修复后的日志通道单独标记，原版碰撞证据保留。仅修改文件名不等于源标签实例身份已经唯一。
2. **线程状态**：验证任务提交时上下文捕获、worker 进入时绑定、异步结果标签回传，
   以及完成/异常/取消后清理。OTel 上下文和污点状态分别验证；OTel context 传播不自动搬运标签。
   不能用全局污点池、普通 InheritableThreadLocal 或串行化所有任务冒充请求隔离。
3. **请求连接**：按实际 RPC 调用、服务端接收与消息字段实例关联。Trace ID 仅是请求上下文，
   同一 trace 内重复调用还需区分实例；禁止按字段值或相近时间补连。
4. **忠实性**：先在受控夹具上比较原版同步路径与适配异步路径的中间/最终标签，
   校准对象、primitive 字段、多源合并和覆盖行为；再做同值不同请求、线程池复用及异常清理检查。
   若修改来源标识、传播规则、日志结构或服务配置，分别披露；不能用适配成功反向证明原版成功。
5. **真实 RQ1**：资格通过后复用已有 15 个真实 API 工作负载；用独立运行级真值评分。
   原有业务未变且已通过的 plain 不必重复采集来替代适配推进，相关新增接口与行为变更再定向核验。

建议保留四个配置，并与我们的方案分开：

| 配置 | 作用 | 结果名称 |
| --- | --- | --- |
| 原版公开 JAR | 原始接入结果与失败证据 | MirrorTaint original artifact |
| 原版传播＋日志适配 | 校准记录完整性 | MirrorTaint + logging adapter |
| 原版传播＋日志／线程适配 | 校准同 JVM 异步传播 | MirrorTaint + logging/thread adapter |
| 原版传播＋日志／线程／请求连接适配 | 跨服务外部传播对照候选 | MirrorTaint propagation + integration adapters |

这些配置是待实施的分阶段校准，不是四个独立外部算法，也不是已经通过的结果。
适配后的端到端成本必须包含全部适配成本；不能标成原版 MirrorTaint 整体性能。
即使采用公共连接层，也不能把其输出当独立准确性真值。
