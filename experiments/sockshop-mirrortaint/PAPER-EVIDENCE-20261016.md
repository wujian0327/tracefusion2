## 3. 内部消融主表：选择性观测减少了什么

每个应用内部的 full/selective 共用同一采集器、事件格式、冻结计划和离线核心，保持当前查询答案。两个应用的 profile 和原业务不同，是独立实验块，不比较绝对成本，也不拼成统一速度提升。full 是已纳入应用类和冻结根调用范围的观测，不是整个 JVM 所有指令追踪。

## 5. 每条结论的边界与未覆盖比较

| 结论 | 必须同时披露的限制 |
| --- | --- |
| 指定字段来源恢复正确 | 来源从已声明的实际响应/实体边界开始，不覆盖数据库完整历史或所有业务路径；值只校验，不按同值配对；保留具体调用span、JSON路径、对象及已观测版本 |
| 自动选择性观测有效 | 查询入口/目标由配置声明；Train Ticket新增通用 List/Map/字符串转换/异常模型，另有手工 JsonUtils/Jackson 库摘要，迁移并非零修改；不保证最小观测集 |
| Train Ticket多来源聚合可迁移 | 保留索引/分支选择证据，但来源TP只计算数值操作数数据依赖，不声称一般隐式控制流；只读集合 epoch 不是任意写入历史 |
| 比 MirrorTaint 部分指标更低 | 只限共同 total、具体版本与适配器、当前机器/输入/资源/负载；不是工具全部能力排名 |
| Phosphor / FlowDist 已有实验 | 保留较早聚合语句与披露模型实验；未校准最新共同字段实例成本任务，对本页主表为N/A；不能写三种外部工具均完成同口径成本比较 |

两应用当前前端主要是 Java Agent。Go 服务参与业务/边界响应不等于本轮实现了其内部字段传播；早期多语言实验不能自动成为这套完整跨服务链的通用保证。任意共享可变集合、反射/native写、自定义集合/序列化器、一般循环及未建模调用超出当前声明范围，应拒绝或保留 unknown。

五轮是五个部署配对，不将同一部署内请求当作独立重复；区间和符号检验是小样本探索性描述，不称统计显著或总体稳定。每部署约120个测量请求，p99很受最慢少数请求影响，主文优先p50/p95。30秒固定预热不证明JIT/GC已收敛。

CPU为声明容器的累计CPU差，不含主机负载驱动/采样器；RSS求和含共享页重复计数，采样峰值不是连续峰值。离线批次包含预热＋测量，不能只除以测量查询数；批次答案等待约一分钟包含剩余窗口及关闭流程，不是固有流式报告延迟。目标创建、原始证据首次可用时点未测，保持N/A。

## 8. 下一步的判断
