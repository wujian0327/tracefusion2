# ZLT 两入口与通用读取收缩：模型边界

参照版本为 `c1a4e5c`，开发基点为 `e99b8b2`。原首次结果、MT B2.2 导出、15 项 unknown 及失败记录保留。本文件说明新增机制，最终能力和成本结果另报。

| 机制 | 适用条件与取证 | 失败保护 |
| --- | --- | --- |
| CGLIB 转发 | 原 ZLT 的八个 Spring 类哈希与既有规则完全相同；补齐模型依赖清单后仍核验实际空 advice 链、SingletonTargetSource、目标、参数与完成 | 不是新增版本白名单；非空 advice 或错配仍不获得解释 |
| Page 构造与字段 | 从原依赖 JAR 导入 Page/IPage 字节码，使用已有构造链、真实 Frame 和字段版本解释 | 不为 Page 的业务字段手写传播公式 |
| Long 与空列表 | 既有 8u504 运行时内的有限装箱、拆箱和空列表语义；依赖按实参位置传递 | 同一个缓存装箱对象不能合并两个来源；值矛盾、缺证明拒绝 |
| Function/Consumer 与顺序集合 | 实际 SAM、捕获参数、方法体、终端调用 ID、成员与阶段；非平凡静态实现类须在根进入前完成初始化 | 回调错配、结果次序、collector 配置改变及缺初始化证明拒绝；未知回调不当作已解释 |
| 默认 SELECT 结果局部性 | 实际 mapper/template、默认构造与完整对象图分配；实际 factory、wrapper、reflector、invoker、type handler；禁止 nested/lazy/L2 缓存；非事务会话关闭并清空缓存 | 无证书继续保守失效；不创建来源，不移动原 mapper 边界 |
| 分配前回调 | 只支持精确的 MybatisPlus 外层分派，观测全部实际 InnerInterceptor 调用；允许回调有副作用，但每次必须在最终返回对象图的全部分配之前结束 | 还要复核回调后的实际映射与赋值实现，并排除结果处理器留存对象；不把租户、日志或角色查询声明成只读 |
| effect-only 方法体 | 静态证明根正常返回同一个来源对象；直接 void 调用另需运行时证书、无发布及参数/接收者隔离 | 条件不满足时采全；引用存储、捕获、传出及源对象写入保守撤销资格 |

最后一项实际省略受保护方法体内的字段读取值与分支记录。Frame、调用、实参、异常完成、所有写入/版本/别名/发布、来源和通信及契约证据继续保留。离线将该方法体作为有任意保守副作用的调用处理，而不是只读方法；运行时发现与私有对象隔离条件矛盾则使捕获无效。

Source SQL 局部性新增的是有限默认映射协议，不能推广到任意 MyBatis 插件、对象工厂、类型处理器、事务缓存或任意 Java 程序。反射/native 任意修改和并发共享修改仍在模型边界之外。监测检查本身只读取原始字段、对象身份及已核验实现，不执行未知应用 getter、toString 或回调。

开发控制包含真实工厂/属性 invoker/查询插件泄露同一对象、间接发布、同值覆盖、回调后修改映射、collector 改写，以及异常后同线程正常请求。完整工件位于 `artifacts/zlt-completion-slice-20261031/`；开发试点与后续同一冻结候选验收分别保存，不称未见查询。
