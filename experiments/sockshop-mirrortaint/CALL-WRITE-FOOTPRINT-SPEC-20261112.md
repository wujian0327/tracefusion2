# 条件调用写入范围：修订前规范

输入是已核验原字节码、静态栈定义、所有计划候选、该次Frame的实参和分支前已执行的堆事实。输出是实际物理对象／声明字段的写集合及尚未闭合的效果；不是按字段名与所有引用参数做笛卡尔积。

1. 从PUTFIELD的接收者定义反向构造形式参数或this起始的字段访问路径；局部别名、实参换位、宽参数槽位和已计划接口候选须保留。
2. 沿调用链逐层替换形参，只在当前调用点绑定实际对象。路径每条引用边须在分支之前已有核验写入／读取证据，版本、身份、选择和不透明影响须闭合。不从后续GETFIELD、快照或同值推导较早许可。
3. 对全部候选先解析再提交。任何可能写入同时改写所依赖的路径引用（包括不同实参实际别名）都不授予此受限证明；缺路径、未知／null地址、未闭合返回别名和不透明嵌套效果明确为能力限制。新容器和包装不自动私有。
4. 闭合集合内未执行写的物理字段携带条件selectors及必要unknown；真正执行的写仍由原解释器记录原版本和值。后续无条件写清除旧物理字段的合流状态，但不能清除已产生值携带的选择。
5. 实际调用、Frame、PC、方法实现、写入、完成、异常和粘性失败仍按旧协议核验。不新增Agent事件、框架契约或异常构造只读摘要。

新JVM控制固定11种形态×0/1输入：直接、嵌套、局部别名、换位、实参同对象、二级转发、两种接口实现、无关实际参数、汇合后引用替换、汇合后独立新值。前8种选择来自实际20号读取；第8至10种目标不受该分支影响。输出7相等不合并10/11号来源。另两次引用边改写控制必须明确拒绝，不能输出空selectors的known。

原66项及6个异常构造unknown保持原预期，不以本控制取代。原报告成绩不改写；旧完整捕获只作新离线复算，无新应用或性能测量。
