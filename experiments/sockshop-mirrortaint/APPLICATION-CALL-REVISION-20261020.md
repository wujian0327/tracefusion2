# 非递归应用调用与字段效果

后续当前进展见[Orders 端到端修订](ORDERS-END-TO-END-REVISION-20261021.md)及[机制](ORDERS-END-TO-END-ALGORITHM-20261021.md)；下文保留本阶段历史结果。

**首版能够依据原字节码和实际调用证据解释非递归应用方法，共享字段及容器依赖状态，并将返回值或异常交回调用者。** 冻结版本为 `87226aaf5bf8d996c9a87f4388b863b8a2795d94`。控制程序 full/selective 各 34 个有效目标中，26 个已知来源全部匹配、8 个必要不透明效果保持 unknown，另各 2 个根异常退出。原版 Station/Route 的 60 个循环目标在新 Agent 捕获及最终离线回归中保持正确。

本阶段没有宣称修复新的基线差距实例：开发台账仍是原 169 个中修复 60 个、剩余 109 个；不是新版整体正确率。原 62 查询、431 目标首轮结果和成本表不改写。29 个未测候选继续按原封存协议保留，没有规划或执行。

## 自动生成的调用计划

新路径同时启用 `execution_kernel: true` 和 `application_calls: true`。规划器从入口的调用指令发现有字节码的应用方法，按冻结类层级枚举受支持的实际实现候选，建立非递归调用图。getter/setter、窄参数赋值构造器和明确公共契约保留快速路径。未支持的子方法列入 opaque_methods 及原因，不因存在字节码就宣告其行为已解释。

方法的候选读写字段、调用位置和异常表从字节码产生，不按业务 helper 名称提供传播摘要。运行时必须核对实际接收对象、进入的方法实现、父 Frame、调用位置、参数及完成结果。静态调用和类层级内的虚调用分别核验；递归、同步方法、接口 default 分派和未建模的外部静态初始化仍是边界。

每个被调方法有独立 Frame、局部变量、操作数栈和程序计数器。接收者与实参绑定到实际局部槽，返回值依赖交回调用者；字段、分配对象、列表和迭代器状态由本次根调用共同维护。新对象复制输入字段、setter 改写字段、局部列表跨方法传递，最终都连接到同一实例依赖图。

来源仍从原声明的根入口参数、仓储读取返回及实际 RPC 读取开始，不把每个 helper 参数重新当作新来源。数值只用于一致性检查。构造器与已解释写入按真实对象和版本建立新状态，目标返回快照继续只负责绑定。

## 字段效果与不透明屏障

已解释的写入只改变相应字段版本的依赖；修改 other 字段不会自动抹掉已证明的 text 来源。已解释的常量覆盖具有新版本和空数据来源，即使新旧数值相同。

未解释调用的返回值保持 unknown。对其可触及的接收者、参数、已逃逸引用和可能全局别名，沿已观察到的字段/容器引用保守失效相关状态。非本地输入及来源对象不能仅靠前后数值相等宣告未修改；不透明调用后尚未重新建立的字段来源继续 unknown。

一个已复制标量来源、未传出且未逃逸的新 DTO，可以保持其字段依赖；如果它通过包装对象流入不透明调用，嵌套别名也须失效。控制程序分别验证这两种情况。模型仅适用于当前声明的对象、标量和库语义；反射/native、任意可变标量实现及并发共享修改不由此取得保证。

## 异常与分析状态

调用记录有采集进程内唯一 call-id，并记录正常或异常完成。被调 Frame 的正常返回、异常退出及调用者的原异常表一起解释；异常对象重抛时核对身份，不以同类型的另一个对象替代。小程序覆盖嵌套异常、调用前空接收者、直接空字段读取、捕获后回退、重抛及后续正常请求。

当前异常层次模型限于已处理的 NullPointerException、IllegalArgumentException 和显式 catch-all；未建模的异常层次分派返回分析能力限制，不猜测 handler。调用缺失、重复 ID、错误父 Frame、错误实参身份或丢失必要写入仍属证据问题。

| 情况 | 状态 |
| --- | --- |
| 完整证据下，静态或离线预算耗尽 | analysis_limited |
| 必要语义不透明，但证据完整 | unknown |
| 采集未关闭、序列断裂或必要完成证据矛盾 | evidence_invalid |
| 业务没有生成目标 | N/A，另列异常根 |

实际完整 JVM 捕获在降低离线预算后抛出 AnalysisLimit；评分层的单元检查确认目标计入 analysis_limited，不能计成 N/A 或 evidence_invalid。静态分析超过预算不输出部分计划。

## 不动点与实例坐标

单方法定义域由有限指令位置、接收者/参数定义及有限局部槽组成。每个栈位置和局部槽保存可能定义集合，汇合使用集合并；局部变量只有在所有到达路径均初始化时才可用。控制流回边及支持的异常边加入工作表，直到队列为空。

方法大小限制为少于 5000 条指令，工作表预算为指令数平方；离线每根请求默认最多解释 100000 步，跨被调 Frame 累计。达到预算前没有达到不动点就返回 analysis_limited，没有将截断状态当作完成。不动点只说明在该模型上收敛；候选覆盖还依赖受支持指令的转移、保守控制流边及调用实现候选。首版不做切片收缩，而是提前保留全部已计划方法的调用、读取、必要写入和路径证据，再逐项消费实际证据；不宣称任意 Java 程序分析完备。

同一指令位置重复执行不能共用实例：服务内 Frame ID、call-id、事件序号和线程区分实际调用；字段使用对象、字段及真实写入版本；容器使用对象、位置/键和内容阶段；每次 NEW 的离线分配 token 独立递增，再核对真实对象身份。指令位置只标记静态站点，不充当动态实例 ID。重复 Frame ID 也被拒绝。

小程序 18 种行为各重复两次，覆盖对象/字段返回、新 DTO 复制、字段改写、无关写入、void 和标量返回、跨方法列表，以及不透明别名和全局效果。真值是独立定义的入口字段或常量来源，不从 TF 图或基线标签获得；预期 unknown 是保护测试，不合并成准确率。

## 冻结和工件复用

初始冻结为 d06be34。原版 Station/Route 在该版本用新 Agent 完成八次部署。Cart 首轮因 Sock Shop JDK 版本未登记而拒绝；无网络原镜像探针核对后，显式登记该运行时，四类库字节码哈希与既有运行时一致，未放宽检查。第二次记录暴露物理快照仅使用 JavaBean 序列化属性，遗漏非标准命名的只读字段访问器，独立真值不能落地。两次记录保留，未作为成功结果。

最终 87226aa 将原字节码核验的物理字段访问器纳入边界快照，与 JSON 线上属性模式分开；它不意味着这些字段都被序列化。随后在新目录重新构建并重新运行 Cart 两配置。

Station/Route 的最终生成计划与原八份执行计划完全相等，最终 Agent 全部 class 字节码哈希也相等；因此复用这些原始捕获，以最终离线代码复算，不机械重新部署。小程序捕获亦有相同计划和 Observer class 核验。实际 Agent、计划和捕获哈希见审计，不把复算冒充新的独立部署。
