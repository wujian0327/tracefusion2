# 构造器效果、静态读取与字符串依赖

本轮扩展统一执行内核的通用语义，没有增加 Orders 字段专用传播公式。调用图仍由固定字节码生成，运行时按实际对象、调用、字段版本和路径核验，离线计算依赖。新机制不等于保存或异步已经被解释。

## 构造器也是有生命周期的调用

构造器分为已核验的参数赋值、可解释的应用 Frame、有限公共契约和不透明构造器。构造器无法解释时，计划记录原因及保守效果；实际没有执行该分支，不需要凭空补入其效果。实际执行时，返回对象和可能受影响的参数、非本地状态不能获得来源保持承诺。

监测器为每次原 `invokespecial` 记录构造器开始和唯一ID，然后记录正常完成或异常完成。开始只记录安全的实参，不读取或传出未初始化接收者；只有原调用成功后才读取实际对象。离线核对调用者 Frame、位置、ID、参数、接收者与完成次序。构造器内部出现的已观测应用 Frame 必须闭合；不透明区段的内部读写不冒充已解释的传播。

编译器生成的内部类可能在 `super` 初始化前写入 `this$0`。当前采集器没有这次写入的初始化后接收者证据，因此赋值快捷模型拒绝这一形态，回退为不透明构造器。不会把初始化后相同的字段值当成已经记录了原写入。

未知构造器可能修改 Date 等可变参数。完成后的快照先应用保守失效，再核验引用身份；不会把允许但未解释的状态变化误标为证据损坏。调用前快照仍严格核验，缺失或矛盾的生命周期仍拒绝。调用前复制出的不可变标量，可以在后续已解释的新对象计算中保留原来源；被修改的旧对象字段不能获得同样待遇。

## 静态读取保留实际值与初始化屏障

`GETSTATIC` 记录实际字段、描述符、指令位置和观察值。静态值尚无声明的来源模型时保持 unknown，不因它恰好是一个字面量就宣称空来源。

外部类初始化可能有副作用。若读取期间执行了已观测应用 Frame，先核验其闭合区段，再对可能受影响状态施加不透明效果屏障；不会以“只是读取一个静态字段”为由认定只读。初始化尚未正常完成而缺少读取完成证据的路径不由本轮获得通用支持。

## 本地 StringBuilder 与实际渲染回调

有限契约使用固定 JDK 的 StringBuilder 和 AbstractStringBuilder 类哈希。仅为已观测创建、受支持的本地 builder 维护内容依赖；支持字符串、null 和声明范围内的基本标量追加及 `toString`。运行证据记录内容前后状态、返回身份和库哈希，来源来自实际操作数，数值与字符串内容用于一致性检查。

`append(Object)` 可能执行应用代码，不能整体标成只读。规划器根据字节码类层级发现应用 `toString` 候选，运行时按实际对象类型、接收者和调用 Frame 选择并解释。已解释的字段改写按实际版本进入共享 State；渲染产生的字符串依赖再进入 builder。未知的库对象渲染、不支持的实现或已逃逸的不透明修改继续施加屏障。不会为取得字符串再调用一次用户的 `toString`。

字符操作数按 JVM 的整数代码单元采集，补齐原来仅记录装箱对象身份的问题；数值常量指令与参数绑定一并核验。本轮未扩展任意 CharSequence、任意 builder 方法、并发共享 builder 或所有 Java 格式化语义。

## 能力边界

上述机制让原版 Orders 入口能够进入统一内核，并保持“不透明效果不变成确定来源”的规则。Future 的提交、工作任务、完成和 join 尚未形成实例协议；HATEOAS 内容与实际读取的来源连接、保存回调和字段效果，以及部分 URI、正则、集合和 Date 渲染仍存在不透明环节。需要逐类建立可核验模型，不能由当前的计划接纳率推导端到端可回答率。
