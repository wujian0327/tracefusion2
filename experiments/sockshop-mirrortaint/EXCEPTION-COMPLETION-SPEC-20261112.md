# 共享异常完成转移：修改前规范

数据参数只参加实际计算／写入的origins；它们不会因调用抛异常而自动成为selectors。正常或异常完成的条件由解释过的被调用者导出；调用者另补该操作自身已核验的必要守卫。缺少完成证明与证明为空必须区分。

- 显式ATHROW：活动控制及实际异常引用的选择／来源，保留原异常身份和分派验证。
- GETFIELD／PUTFIELD空引用：接收者是守卫，写入载荷不决定空引用失败。
- JVM数组：负长度用长度；空数组引用用接收者；越界用数组和索引；类型不兼容另需要存储引用的类型／选择。不能把不参与失败条件的存储载荷一律加入。
- 调用：接收者空引用属于调用者；已解释callee的异常完成条件属于callee；旧有限库模型可在核验原操作事实后提交明确的异常守卫。没有这些证明的非空opaque调用不能产生完整known选择答案。
- catch：消费本次异常完成及必要守卫，在原CFG汇合处结束；不能合并全部consumed调用参数。abort／逐层重抛使用同一公共规则。catch消费后清理，新的调用实例／根请求不继承旧异常状态。

不删除consumed：它仍提供本指令的原始操作数，公共规则按JVM位置挑守卫。源缺失／歧义或必要效果未知保持unknown；错Frame／PC／身份／顺序／完成及粘性失败仍拒绝。

原构造补充case8的2个目标必须按原预期通过；原6项构造unknown及case5的2项覆盖调用拒绝保留。不修改JDK/native构造效果，不新增框架。本轮新控制覆盖已解释调用的无关参数／实际异常条件、隐式空引用、数组越界与无关存储载荷、嵌套／重抛／finally／后续正常请求。所有预期由程序规则与各JVM原始来源事实生成。
