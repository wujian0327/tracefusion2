# 有界调用链与读取对象的生命周期

本轮在统一执行内核中补充两项机制：允许应用 helper 的静态调用图有环；用已核验构造器中的对象创建证据，区分不透明效果发生前后出现的对象。保存仍是不透明调用，没有新增“save 保持所有字段来源”的摘要。

## 有限调用图与实际调用 Frame

规划器按原字节码发现调用与 lambda 实现。每个方法只分析一次，静态方法集合有限，遇到已发现的方法保留调用边，不再因 helper 调用图成环而排除整个回退函数。具体实现、参数、接收者、父 Frame、调用位置及正常或异常完成仍逐次核验。

离线按实际执行创建独立 Frame，局部变量与操作数栈独立，字段与容器状态共享。默认每根请求累计最多100000步，最多64层调用；完整证据下超预算为 `analysis_limited`。这不证明程序终止，也不保证任意递归均支持。查询入口本身重入另记 `analysis_limited`，不把嵌套入口误作互不相关的新请求。原有同步方法、未建模指令与框架效果限制保留。

## 构造器创建证据

只对已纳入执行计划、已固定类哈希的构造器生成创建观测位置。首版要求原字节码以 `ALOAD 0; invokespecial Object.<init>()V` 开始。在这个位置之前，业务构造器尚无机会将该引用传出。监测器在原初始化成功后读取对象，不向监测器传入未初始化的 JVM 引用。

`execution-object-birth` 记录实际对象、构造器、Frame、事件序号和类哈希。离线要求匹配同一构造器 Frame 的接收者和进入顺序；同一对象重复创建证据、错误身份或类哈希不能被用于恢复来源。继承结构不满足该前缀、缺少该观测或对象已在先前请求创建时，不能仅凭“第一次看到这个值”认定对象是新建的。

旧内核预先索引整根请求中的来源快照。不透明效果的保守失效集合因此可能包含稍后才创建的读取对象。本轮仅在创建证据证明对象尚不存在时，将它排除于更早效果的可达集合：

```text
不透明效果完成 → 新对象的构造器创建证据 → 实际来源读取返回 → 字段使用
```

效果发生前已存在的对象、保存参数、已逃逸别名以及没有创建证明的对象继续保守失效。对象创建后再发生不透明效果，也继续失效。并发共享修改、反射/native 写不由此取得支持。

**创建证据只约束效果的时间范围，不创建来源边。** 已知来源仍必须由原先声明的入口、仓储读取返回或已核验 RPC 读取提供，并匹配具体对象、字段、版本和调用实例。局部计算与写入仍由执行内核解释；返回及序列化快照仅用于目标绑定。

## Cart 首次创建的实例

原版 Cart 的空结果回退实际执行创建和保存，丢弃保存结果，然后再次读取。第一次 GET 的 `customerId` 来源是第二次仓储读取返回的实体字段；下一次 GET 则来自本请求的第一次读取。两者值相同，但调用与对象实例不同。

本轮解释回退 lambda 和再次进入的 helper；save 的返回值及可能受影响的旧状态仍未知。第二次读取中的实体在 save 完成后才由原业务类构造，实际来源边界再提供该实体字段，因此可以回答这个目标。若业务直接返回保存参数或保存结果，就不能套用此结论；Orders 的保存、异步链也没有因此获得支持。
