## 实现与边界

规划器从原字节码核验受限的 `this(...)`／直接父类构造链。进入初始化调用前只接受接收者、实参及常量的纯加载；不支持的前置操作、初始化副作用和构造形态继续不透明。构造体指令、异常分派及执行预算仍受内核原有边界限制。没有为 MyBatis 生成类或业务字段增加专门传播摘要。

父、子构造方法各有实际 Frame，共享外层构造调用 ID、同一个分配 token 和实际对象身份。初始化前不把未初始化引用传给监测器；父构造返回后才记录子构造 Frame。离线按字节码链、实际实参、共同外层调用及对象身份连接这些 Frame，不伪造初始化前的父 Frame。

在终端 `Object.<init>` 成功后、字段赋值前记录整个受支持继承层级的默认字段事实，核验真实运行类、声明类哈希、字段覆盖及版本 0。父子构造的后续写入在同一状态中建立新版本。字段引用按 JVM 声明类解析；父子同名字段保持不同坐标，继承访问器还要核验实际实现。

这里扩展的是执行状态和字段访问；没有同时扩展任意继承对象直接作为响应时的 JSON 投影。

此次也补了实际需要的 `INSTANCEOF`：记录原 JVM 判断结果、输入对象、目标 Class 和实际类层次，离线核验后执行转移。不是只让规划器接受 opcode 193。当前只支持已声明、可核验的目标类型，不宣称任意动态类型支持。

完整解释的构造只应用它实际执行的字段／容器效果；必要不透明回调、发布或全局效果仍保守失效。因此“新对象构造”本身不是无副作用证明。一般框架调用的影响范围分析尚未完成。
