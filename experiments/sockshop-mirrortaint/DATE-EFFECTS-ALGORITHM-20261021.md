# Date 语义状态与按需公共契约

本轮延续统一执行依赖内核，不按订单字段名补传播规则。新增有限 Date 效果，另修复公共契约的启用条件；原业务 JAR、声明的来源边界及字段实例定义保持不变。最终冻结为 `2cefacdc577b4bf1b8635201efcacf58c221ab85`。

## Date 的语义状态

精确 `java.util.Date` 的本轮状态是对象身份和 epoch 毫秒。固定 JDK 的 `getTime`、字符串渲染可能整理内部日历缓存，因此不能把物理字段完全不写当作前提；也不能仅凭前后毫秒相同证明来源没有变化。

渲染调用同时要求：实际接收者或参数为精确 Date、调用开始和完成闭合、Date 身份与毫秒一致、相关 JDK 实现哈希属于固定运行时、默认时区是受支持的 ZoneInfo。直接 `Date.toString` 和 `StringBuilder.append(Object)` 经此检查，可以保持 Date 的数值来源状态。渲染产生的字符串仍保留 unknown，本轮没有完整解释字符串的时区和格式来源。

同值 `setTime`、必要不透明 helper、自定义时区等不据数值相等恢复来源。原先已失效的来源也不会因后续默认保存而恢复。

## 保存中的实际编码器

保存仍须满足已有实体、字段写入、ID、转换器、事件和回调检查。除此之外，本轮在 Mongo 实际 `CompoundDBObjectCodec.encode` 调用处记录：真实底层编码器和 DateCodec、默认注册表身份、编码钩子状态、ID 生成器以及固定版本类哈希。离线核对这些证据的数量和调用闭合。

只有实际使用受支持的默认编码链且没有全局编码钩子时，才能不再为该有限保存额外抹除私有 Date 的状态。自定义编码器、转换器、保存回调和无法证明的共享别名继续导致 unknown。返回同一对象或前后毫秒相同，都不能单独证明来源保持。该模型没有把任意 Mongo 保存概括为只读。

原版订单日期由实际 Calendar 调用产生；在既定入口、仓储和 HTTP 字段来源边界上的投影为空，但它仍是环境时间，不能称为常量。独立真值核对实际 Calendar 返回对象、目标字段及客户端 ISO 时间，不从 TF 推断空来源答案。

## 运行前选择执行策略

统一策略同时检查旧 profile 与执行内核的静态支持条件，依据字节码中的数组、循环、lambda、任务、保存等结构决定路径；专用标量/复制证明保留优先级。所有查询的选择和完整计划在业务运行前保存，不读取预期来源或基线正确标签，不在运行后挑选成功的 profile。

新增效果协议只在静态计划实际涉及任务/保存或 RequestEntity 操作时启用。首轮策略曾给普通 TicketInfo 转发附加不适用的 HATEOAS 契约，导致运行时类加载失败；失败捕获保留，修正后另行冻结。缺少必要模型仍应 unknown 或拒绝，不能借此关闭正在使用的必要核验。

## 接收集合与类型边界

执行内核不再给所有接收集合附加旧只读 profile 的执行保护。业务允许追加元素；精确支持的本地未逃逸列表仍建立来源，无法证明所有权的接收/逃逸列表则核对实际成员增量和内容阶段，保守失效相关状态。它不把未支持修改改写成业务异常，也不据修改前后同值恢复来源。旧只读 profile 的约束保持。

UUID 目标尚缺序列化投影，两条规划路径统一报告目标类型不支持，不再产生目标快照缺失的伪接纳。它不影响其他字段的来源支持。
