# Sock Shop 有限读取模型与来源证据修订协议

日期：2026-10-20。沿用原版业务 JAR、原来源边界和前轮结果；本轮不做性能实验。

## 顺序与范围

1. 在核心改动前提交 `0dca193`，封存剩余49个候选中的每应用10个查询；未选的29个不尝试规划。所有入口都曾在前轮使用，因此仅称“旧入口新字段”。原20+22查询现在都是开发资料。
2. 独立记录实际 HTTP 输入字节、RPC 实例与解码对象/字段/版本，不把原始事实直接作为来源答案。独立无 Agent 程序使用原业务 JAR 中的库，复现原 `RestProxyTemplate` 的默认 Jackson 转换器。
3. 先打通原有开发集中的 Cart 读取链。只新增有界组合读取效果检查和固定 JDK 的 `List.stream → findFirst → present Optional` 模型。静态检查不允许任意字段写入、循环、反射/native、数组、监视器；每个执行到的子调用仍须单独核验。嵌套方法中只允许标准 LambdaMetafactory 创建 Supplier，执行其回退体不因此被接纳。根方法的 invokedynamic 拒绝保持。
4. 保存和异步不是只读模型。Mongo save、Future/CompletableFuture 工作、HTTP POST helper、未证明的日志 toString 等仍可能造成 unknown。HATEOAS 的固定版本内容投影只补原始事实，本轮不自动证明任意解码器或将所有投影字段建成来源。
5. 原22查询重新回归；另测 Cart 三个开发查询和 full/selective 答案一致性。历史4个规划正控制、业务来源回归、第二组语义与必要证据拒绝保护继续检查。封存测试之前冻结新核心、库版本、参数、JAR 和工件哈希。
6. 新封存查询首次结果独立保存。拒绝不替换；无法支持的输入生成器单列，不能伪装成算法 N/A。发现缺陷只能建立新的开发/修复阶段，不能覆盖首次结果。

## 真值与分母

- Cart：按原业务代码固定投影 `findByCustomerId` 的首条 Cart，`getItems` 再投影实际元素位置；原始仓储字段坐标、合法业务输入/独立客户端读取用来核对。不能用同值替代对象或调用。
- Orders：固定原业务 DTO 引用投影，匹配实际 RPC URI、父消息、原始 JSON 与解码字段坐标。原默认转换器下，ResourceSupport 的忽略属性使原始 `id` 未写入 content.id；默认 null 的预期数据来源为空，不能连接原始 `/id`。用户名等实际解码标量则由对应实际 RPC 字段提供真值。
- 预期来源脚本独立实现上述原代码投影，不调用 TF 的传播、别名或跨服务连接算法。必要原始事实不存在、保存/转换前提无法核验时保留 oracle unavailable，不能强给空来源。
- 查询族、入口组、请求、目标实例、N/A 请求分别计数。实际目标可回答率 = 已知 / 实际目标；已知准确率与含 unknown 的整体来源关系分别报告。默认空来源仍是目标，unknown 不是正确空来源。

## 透明披露

封存后尚未调用新查询的规划器或运行它们，但开发过程中一次查看封存文件头部的命令显示了前两个查询 ID（`carts-addToCart-itemId` 与 `carts-get-unitPrice`）。没有据此调试这些目标或修改选择，也没有替换候选。本轮不称第三方盲测；最终报告保留这一提前查看记录。另一次小程序首次使用重叠对象的两组入参，暴露了重复来源边界的保守 unknown；保留原失败工件，随后将其明确列为独立的歧义拒答测试，并另加不同对象的正常测试。

本轮停止条件是：至少一类真实非空 Sock Shop 链可复用于多个目标并有独立实例真值，保护检查有效，剩余 unknown/拒绝可解释。并不要求 Orders 的保存/异步链或所有查询全部成功。原成本表仅对应旧版；本轮全量调用配对记录本身也有成本，不能直接借用旧性能优势。
