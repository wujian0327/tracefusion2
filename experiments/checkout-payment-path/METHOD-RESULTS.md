# 四组方法对照：主机正确性结果

2026-10-10 核验上传包 `checkout-method-comparison-20261010-005245-034561.zip`。机器为 WSL2/Linux amd64、Go 1.25.4、Python 3.12.3、BCC 0.29.1。本次构建和部署是原始业务测试可执行文件及本机 gRPC 后端替身，不是完整商店生产部署。

**十个 native 用例和四组共 40 次真实 BPF 采集通过。**核验器重新从上传 ELF 重建全部计划/布局、核对源文件摘要、重建 40 份采集器源码，并对全部 **13,478 个原始事件**重新推断，结果与包内推断及独立真值一致。指标从原始记录重算，不仅检查 `all_passed`。

明细及包摘要见 [method-host-validation-20261010.json](method-host-validation-20261010.json)，复核入口见 [verify_methods.py](verify_methods.py)。核验过程使用本仓库的可信代码，不执行上传的 Python 或业务可执行文件。

| 方法 | 精确字段查询 | 错误确定归因 | 原始事件 | perf 样本字节 |
|---|---:|---:|---:|---:|
| 全部相关分支 `all_branches` | 18/18 | 0 | 5,068 | 1,074,416 |
| 当前选择性方案 `selected` | 18/18 | 0 | 4,210 | 892,520 |
| 独立路径敏感切片 `path_sensitive_slice` | 18/18 | 0 | 4,067 | 862,204 |
| 完整边界重放 `boundary_replay` | 18/18 | 0 | 133 | 28,196 |

九个用例产生支付参数，各查询 Units/Nanos；准备失败用例四组均正确报告 no_sink，单列，不计入 18 个有效字段查询。支付失败仍产生待查金额参数。每组关系 TP=285、FP=0、FN=0，固定分母和运行数量完整，无删去未知或失败用例。

相对全部相关分支，selected 少 **16.93%** 的事件；路径敏感组相对 selected 再少 **3.40%**；边界重放相对 selected 少 **96.84%**。数字属于同一 snapshot-v2、同一十用例套件的采集量比较，不是业务延迟或 CPU 改善。

两内部观测组与路径敏感组各观测并重建 143 次 Sum；边界组没有任何 Sum 内部事件，也从指令重放出 143 次 Sum。selected 与 all 相差 858 个事件，对应每次 Sum 六个；path 与 selected 相差 143 个，对应每次 Sum 一个。这说明现有选点策略在该源快照口径下仍保留了可省去的条件观测。

旧 snapshot-v1 的事件数为 all=5,059、selected=4,201；本次各多 9 个请求货币元数据事件，来自九个成功准备的调用。不要把不同边界快照口径直接混成一个性能比较。旧 `boundaries` 主动返回 unknown 的弱控制组，不能替代这里已实现并通过主机验证的边界重放。

## 采集和支持范围

- 报告的 lost、read_errors、submit_errors、namespace_errors 全为零；每个样本 212 字节，事件结构 208 字节，计量不含外层 perf 记录头，也不等于 JSON 大小。
- 命名空间差异诊断计数共 13,478，记录宿主 PID 与已绑定命名空间 PID 的差别。源代码和事件中的 PID 过滤均按捕获时的 namespace 绑定核对；该诊断不是丢失/读取错误，不能把它误写为零。
- 金额区间没有观察到线程迁移、调用方栈地址变化或实际 gcWriteBarrier/wbMove 调用。边界推断执行的 104 次屏障分支等价检查，是静态指令与运行时契约的推断检查，不是自然 GC 路径覆盖。
- 十项丢失/G 错配/缺源包/错目标值/不支持指令检查重新通过；它们是离线故障注入，不是额外十次内核实验。
- 来源止于准备结果中的价格/运费。对象不可变、Money 源对象不同、Go/amd64 ABI、数量及字符串长度上限、运行时摘要等契约仍适用。完整边界重放不等于无需输入快照或支持任意程序。

## 对论文的影响

**更强基线在当前固定、不可变的金额输入范围内只凭完整边界快照就足够恢复来源。**这已由真实采集核验，不再只是本地模拟现象。

已有证据支持原始业务路径正确恢复来源、选择性方案相对全部分支减少采集。已有证据不支持“selected 在采集量上优于这些强方法控制组”，也不支持“这条路径必须观测内部条件才能恢复来源”。不能用弱边界推断器返回 unknown 掩盖本次结果。

本轮三个分析实现仍是本仓库的方法控制组，不是论文作者工具的复现；外部工具对比尚未运行。当前也没有这四组同口径的正式延迟/CPU结果，原生单请求时间与单次离线推断计时不能充当性能评估。

下一项应是正确性通过后的**同负载完整成本评估**：保留无 BPF 的业务基线，比较四个方法控制组的业务延迟/CPU、采集进程 CPU/内存，以及独立列出的离线推断时间/CPU/内存；构建、BPF 编译/挂载和离线静态计划耗时分开。边界重放的额外指令执行与定义图成本要纳入评价，不能只测业务进程。

若完整成本也没有优势，就收缩这条路径的优势主张和论文贡献范围。正确性实验已通过，无需重跑旧金额正确性或 Hotel 日期实验，不默认追加一个小场景来制造胜出结果。

## 复核命令

使用同一版本 Go，在仓库根目录运行：

```bash
python3 experiments/checkout-payment-path/verify_methods.py \
  --archive /absolute/path/checkout-method-comparison-20261010-005245-034561.zip \
  --go /usr/local/go/bin/go \
  --output /absolute/path/method-validation.json
```

此命令只重建计划与离线核验已有记录，不挂载 BPF。
