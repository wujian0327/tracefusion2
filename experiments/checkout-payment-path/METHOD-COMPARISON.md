# 原始支付金额路径的独立方法对照

状态（2026-10-09）：实现及本地检查完成，**新四组主机 BPF 比较尚未运行**。不是正式性能结果，不是 HardTaint、libdft 或论文作者系统的复现。

本轮只复用原始 `PlaceOrder → MultiplySlow/Sum → chargeCard`、既有十用例和独立真值，不追加业务函数、语言或应用。论文起草暂停。

## 四组比较什么

| 组 | 内部观测 | 推断 |
|---|---|---|
| `all_branches` | 调用方、MultiplySlow 的控制/地址/调用证据，Sum 全部分支 | 现有生产推断器 |
| `selected` | 调用方同上，Sum 选择性分支 | 现有生产推断器 |
| `path_sensitive_slice` | 调用方、MultiplySlow 的控制/地址/调用证据，Sum 仅入口/返回 | 独立指令解释、定义图及目标字段向后依赖查询 |
| `boundary_replay` | 源快照、支付边界、PlaceOrder 完成 | 从完整源快照执行原始指令；不读取任何内部事件 |

后两组共享新的有界 amd64 解释器，但不调用现有 `Frame`、数值路径枚举器或分支选择器。它们只获得经过 ELF 字节校验的指令、ABI/字段绑定、事件位置和所采事件；不读取生产选点结果、测试用例配置或真值。路径敏感组的调用方探针集合是显式保留的公共观测集合，不宣称已求其最小切片。

解释器对每个调用建立栈状态，按实际指令执行循环和嵌套调用。寄存器/内存的完整覆盖替换旧定义；算术建立直接数据依赖，最后从目标字节向后查询源字段。相同数值不合并字段标签。条件影响单独记录；Quantity 是循环控制，不作为本次 Money 数值字段查询的源标签。

`path_sensitive_slice` 使用所采调用方条件和地址，Sum 内条件由入口数值和代码独立计算；Sum 出口数值只作一致性核验。`boundary_replay` 的所有普通条件由快照和代码计算，支付数值只在推断完成后检查一致性，不能用相等值选择来源。

边界组没有快照 Go 的全局写屏障状态。它在每次屏障分支处执行快/慢两种替代路径，并检查汇合点的活跃寄存器、栈和全部已声明应用内存一致；只有满足这个条件才合并。私有屏障缓冲区与应用内存分开。屏障、分配和字符串比较使用明确运行时契约，不能写成完整 GC 或任意运行时执行支持。

## 相同输入与计量口径

旧边界快照只有价格/运费值和数量，无法完整重放对象图和货币比较。新四组统一使用 **snapshot-v2**：

- 原有源返回寄存器、Money 地址和 Units/Nanos、数量。
- 每个商品的 OrderItem/CartItem 地址及 Money.CurrencyCode 指针、长度、最多 8 字节内容。
- 原始请求地址和 UserCurrency 指针、长度、内容（一个额外源元数据事件）。

事件结构不扩容，复用带标签源事件中原本空置的寄存器槽。普通事件仍是真实寄存器快照。生产推断器读取经验证后的数值事件视图，忽略额外请求元数据；**报告的原始事件数/字节/丢失统计不扣掉该元数据**。四组均承担相同的源快照成本。旧 snapshot-v1 结果保持原口径，不与新四组拼表。

支持范围仍为 Go 1.25.4/Linux amd64、单调用/进程、最多 32 个商品、各 Money 源对象不同且区间内不可变。此次重放还限定数量 1–32、非空货币字符串最多 8 字节和最多 200000 条解释指令。protobuf 非数值元数据不作为源标签，未捕获的具体值保持未知；未知地址、谓词、调用、指令或目标定义均导致 unknown。运行时契约、源边界和布局需要人工配置与校验。

这四组属于**方法对照与消融**。仍需要独立部署并核验外部强工具，才有资格宣称优于该工具；不能把这里的自实现控制组标作 HardTaint/libdft 的实验结果。

## 当前本地证据与含义

Go 原始业务夹具的十用例通过。Unicorn 执行本次构建的原始 ELF 区间字节，在写屏障快路径、慢路径、交替路径下产生明确标注的模拟事件；四组共 **120 次推断**均与独立原生夹具真值一致。另有十三项丢失/G 错配/缺源包/错目标值/不支持指令/超界货币快照/屏障替代路径写应用内存拒绝检查，以及定义覆盖、同值不同源、算术合并、常量覆盖和内存宽度界限检查。四组 C 语法桩和探针入口检查通过。

这些检查替代了分配、memequal 和屏障的运行时契约，**没有加载 BPF，没有检验内核 verifier，不是自然 GC、线程迁移或正式性能证据**。本地明细见 [method-local-validation-20261009.json](method-local-validation-20261009.json)。

本地结论是：**当前固定且不可变的源图范围内，完整边界输入足以恢复这十用例的来源**。路径敏感组也不必采 Sum 的内部条件。这是更强基线应保留的有效结果；不能继续用旧边界推断器主动返回 unknown 来证明内部观测必要，更不能预设当前 selected 一定胜出。

本次 ELF 的静态位置数为 all=114、selected=106、path-sensitive=103、boundary=7（包括多个返回位置）。它们不等于动态事件数量或开销。不要把本地模拟事件数写成主机采集量收益。

## 统一主机命令

将本轮代码包解压到现有仓库根目录，不必切分支。沿用已跑通的 Linux amd64、系统 Python/BCC 和 Go **1.25.4**：

```bash
cd ~/tracefusion2
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 experiments/checkout-payment-path/compare_methods.py run
```

如果 Go 不在 PATH 中，加 `--go /usr/local/go/bin/go`。可用 `--checkout` 指定干净的 Online Boutique v0.10.4 checkout；默认复用既有 checkout。无需重跑旧 `run.py` 正确性实验或 Hotel 日期实验。

一次命令执行十用例各一次 native 和四组 BPF，共 **40 次新采集**；四组按已记录种子打乱顺序。输出包括二进制、指令/布局/计划、源文件摘要、运行顺序、每例原始事件/BPF 源码/真值/推断、原始事件及字节和丢失统计。异常也生成 zip。返回最后打印的结果 zip 即可。

所有方法使用相同有效查询分母 18；no_sink 单列，unknown 或采集失败不删去。入口不计正式延迟/CPU，离线推断单次计时只是诊断，不能与既有稳态性能表拼接。

不加载 BPF 的本地复现：

```bash
python3 experiments/checkout-payment-path/compare_methods.py build --output /absolute/new/results
# 可选依赖 unicorn==2.1.4，仅本地 ELF 检查需要
python3 experiments/checkout-payment-path/check_methods_local.py --results /absolute/new/results
```

先核验新主机结果是否保留边界充分性，再把通过正确性的强基线接入同负载性能比较。若边界基线仍足够且采集更少，应收缩当前业务路径上的优势主张，并据此审阅贡献边界；不默认开启一轮新增小场景。
