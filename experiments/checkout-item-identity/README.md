# Checkout Item / Cost 对象身份：外部动态观测闭环

这个实验回答两个对象身份问题：

1. 某次 `prepOrderItems` 返回的 `OrderItem.Item`，与本次输入 `items[]` 中哪些对象是同一个对象？
2. 最终 `OrderItem.Cost`，与本次执行中哪些已成功返回的 `convertCurrency` 调用返回对象是同一个对象？

第二个问题停在 checkout 进程内的转换包装函数返回边界，不代表已追到远端 Currency 服务的计算过程。此次没有扩展跨服务字段映射。

采集策略与开销对比现已提供 `compare` 模式，见 [COMPARISON.md](COMPARISON.md)。普通 `run` 仍执行当前 11 个探针的七场景验证。

精简策略已由查询依赖闭包自动生成，并输出每个位置的保留/删除理由，见 [SELECTION.md](SELECTION.md)。这里自动化的是已声明证据语义下的选点；接口语义和 Go ABI 仍由适配器配置。

这不是完整字段血缘，更不是所有中间写入的还原。多个位置引用同一个对象时，输出候选位置集合；不同对象即使商品字段完全相同，也按对象身份区分。地址在本次调用且对象保持存活的范围内使用，不作为跨进程或跨生命周期的永久身份。

## 主机运行

沿用此前运行 BCC 的 Linux/WSL2 amd64 环境，使用 **Go 1.25.4**、Git、系统 Python 3 与 BCC。不需要 Docker，也不需要启动整套商城。首次运行需要下载上游源码及 Go 模块。

在 tracefusion2 仓库根目录执行：

```bash
git pull --ff-only
sudo env "PATH=$PATH" /usr/bin/python3 experiments/checkout-item-identity/run.py run
```

若 Go 没有进入 sudo 的 PATH，可显式指定 `--go /你的路径/go/bin/go`。国内模块下载有困难时，可在 `sudo env` 后增加 `GOPROXY=https://goproxy.cn,direct`。实验不安装或改动系统环境。

此前主机访问 `proxy.golang.org` 下载超时，已通过显式传入代理继续运行；同一环境可直接用：

```bash
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 experiments/checkout-item-identity/run.py run
```

默认下载到 `artifacts/online-boutique-v0.10.4`。已有干净的上游 checkout 可传 `--checkout /path/to/microservices-demo`，必须位于提交 `474d0f2eb73d97525234995a40d7781b7923a07d`。

结束或失败都会打印：

```text
Return this result archive: .../artifacts/checkout-item-identity-时间.zip
```

请返回该 zip。包含编译日志、目标二进制、探针计划、逐场景内核事件、采集计数、独立真值，以及成功推断时的 `inference.json`。失败还包含 `failure.txt`。只运行合成商品数据，不应把此脚本直接用于生产秘密数据。

## 实验组成

- **应用**：Online Boutique v0.10.4 原始 checkout 订单函数。追加临时测试文件，以正常优化的 `go test -c` 编译；构建结束删除测试文件并检查原始受版本控制文件未变。目标是测试可执行文件，尚非原生产二进制部署验证。
- **后端**：本机 gRPC ProductCatalog/Currency 测试服务；执行原始订单逻辑，不启动支付、邮件和完整商城。
- **静态计划**：复用已有汇编、CFG、ELF 偏移检查代码；从 DWARF 取得 `OrderItem.Item/Cost` 布局，识别候选字段写入、切片发布及返回位置，以及指定 `convertCurrency` 直接调用和独占后继。Go ABI 与目标函数/调用边界显式配置，不是任意程序的自动全覆盖。结构超出支持范围时拒绝生成计划。
- **动态采集**：复用 `scripts/string_capture.py` 的进程门控、BCC 挂载、PID namespace 过滤、perf 读取和丢失统计；新 transport 读取对象指针，不采集网络包。探针按目标二进制哈希绑定。
- **推断**：只读取探针计划和内核事件；按 PID、goroutine 身份检查一次订单调用，按内核时间排序，将最终对象与发布时快照对应。Item 查询入口对象集合；Cost 查询该次发布之前成功返回的转换调用集合，不按循环下标对应。转换入口/返回配对，嵌套、缺失配对或未返回即发布均拒绝。OS 线程号不作为调用身份；本实验不专门强制线程迁移或并发。
- **独立评估**：测试夹具另存实际输入/输出指针与 Go 指针相等比较结果。测试客户端 gRPC 拦截器记录 Currency 请求的 `From` 对象和成功回复对象，验证订单 Cost 指针与回复身份一致。失败 RPC 的已分配回复不能当成成功返回值；原包装函数在错误路径返回 nil。真值中保留类型化引用至本次评估完成，避免对象回收后地址复用；这个受控生命周期不是通用 GC 对象身份方案。推断文件生成后，评估器才读取真值；真值不用于选择来源。

当前 v2 本地编译结果为 **11 个物理探针位置**：订单入口 1、候选 Item/Cost 偏移写入 4、转换调用前后 2、切片发布后 1、订单返回 3。这是位置数，不是运行事件数；循环会多次触发。

计划包含 `schema_version: 2`。新内核事件逻辑大小为 840 字节，BCC perf 记录允许 844 字节填充布局；旧 v1 原始事件为 576/580 字节，不应混用。推断器保留旧 v1 JSON 事件的离线回放支持。

## 证据的含义与限制

| 观测 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 入口输入指针列表 | 本次输入包含哪些活对象 | 哪个输入位置后来被读取 |
| 字段写入指令前的操作数 | 即将写入的地址和指针操作数 | 仅此事件不能证明指令已完成 |
| 转换调用前后寄存器 | 本次调用输入 Money 指针、返回对象、错误状态 | 远端数值计算依赖 |
| 切片发布指令的独占后继处快照 | 该发布执行后的订单对象及 Item/Cost 指针 | 之前/之后所有其他写入的历史 |
| 返回时输出指针快照 | 最终 Item/Cost 与哪些已观测对象身份相同 | 内部字段内容的来源和版本 |

写入候选按字段偏移识别，可能包含其他类型在相同偏移的写入；结合实际对象地址及发布快照匹配，不因偏移相同就认定类型。对于同一对象，使用发布前**最近一次观测到的**候选操作数，不能跳过冲突事件挑选较早的相等值。

即使发布时与返回时指针相同，也**不证明期间没有发生相同值覆盖或先改后恢复**。当前不把快照一致当成完整写入历史证据。入口对象没有任何身份匹配时报告 `unknown`；同一对象出现在多个输入位置时报告 `ambiguous_input_position`，不按循环下标猜测。采集丢失、身份不一致、缺失必要发布事件等使本次评估失败。

Cost 的 `cost_source_candidates` 是 `conversions` 数组中从 0 开始的调用编号。只匹配发布之前已成功返回的同一指针；一个指针对应多个返回实例时保留 `ambiguous_conversion_instance`，未找到时报告 `unknown`。此编号来自动态入口/返回序列，不等于输出条目下标。

## 七个场景

| 场景 | 检验点 |
|---|---|
| empty / one | 零次与一次循环 |
| equal-eight / equal-thirty-two | 8/32 个字段值相同但身份不同的输入；各转换回复价格均为 14 EUR、对象不同 |
| aliased-input | 输入位置 0、2 引用同一对象，保留 `{0,2}` 候选集合 |
| product-error-second | 第二次查询失败，已构造条目不应成为最终输出 |
| currency-error-second | 第二次转换失败，已构造条目不应成为最终输出 |

## 已完成与待验证

**Item v1 主机结果已核实**：归档 `checkout-item-identity-20261009-010338-486609.zip` 中七个场景全部通过，共 154 条 BCC 事件，计数吻合，无报告的读取错误/事件丢失。归档二进制哈希与探针指令字节通过检查，所有场景的原始事件离线回放均与独立真值一致。32 商品场景中同一 goroutine 的事件出现在 4 个 OS 线程上。该结果仅支持 v1 Item 身份关系，不能推广为所有字段溯源准确率。

**Cost v2 主机结果已核实**：归档 `checkout-item-identity-20261009-011253-475783.zip` 的七个场景全部通过，342 条事件无报告的丢失/读取错误。二进制哈希、探针指令及离线推断与独立真值均已核对；44 个最终条目的 Cost 匹配相应成功转换返回对象。共观察到 47 次转换调用，其中 1 次失败；失败不产生最终输出。32 商品场景的同一 goroutine 事件出现在 5 个 OS 线程上。

**比较模式主机结果也已核实**：三种策略各通过七个场景和 88 条最终引用关系，全部 39 次 BPF 采集回放一致。32 商品场景五次测量中，精简/当前/密集组事件中位数为 98/226/427，耗时中位数为 32.74/33.51/33.79 ms；native 为 29.68 ms。事件量收益明确，耗时改善较小且存在波动，不能宣称稳定显著优势。详情及口径见比较文档。

查询选点规则已通过 39 项单元测试和上述 39 次采集回放；13 次精简组采集对应的 BPF C 程序与自动计划生成的程序逐字一致。这次规则化检查未重新加载内核探针。
