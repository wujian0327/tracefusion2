# 原始 money.Sum 的执行级字段依赖

本实验直接调用 Online Boutique v0.10.4 原有的 `money.Sum`，不替换其实现、不改 `money/money.go`、不关闭编译优化。新增的 Go 测试夹具只提供输入、调用原函数一次并保存独立真值。仍不是完整 checkout 部署、完整下单流程或跨服务溯源。

## 查询与语义

查询本次成功调用返回的 `Money.Units`（整数部分）和 `Money.Nanos`（小数部分）分别读取了哪些输入字段。输入身份是该次调用的 `l.Units`、`l.Nanos`、`r.Units`、`r.Nanos`，不是通过相同值匹配对象。

- 对复制指令传播来源；算术指令合并读取操作数的字段来源。
- 字节级栈槽区分部分覆盖，32 位寄存器写入清除高位旧来源；建模符号扩展、常量乘法、算术移位和零值清除。
- 记录的是执行级数据依赖，不是数值贡献大小或反事实因果。加零、相消得到零，通常仍有操作数来源。
- **不把隐式控制依赖混入数据来源。** 某字段只影响分支、没有进入该路径的算术时，它是控制证据，不一定出现在输出的数据来源集合中。这不等于断言该字段对输出没有因果影响。

原始成功计算存在两类来源：

| 实际计算路径 | 返回 Units 的数据来源 | 返回 Nanos 的数据来源 |
|---|---|---|
| 执行小数除法进位/取余 | l.Units、r.Units、l.Nanos、r.Nanos | l.Nanos、r.Nanos |
| 整数和与小数和符号不一致，执行常量校正 | l.Units、r.Units | l.Nanos、r.Nanos |

这些集合由真实汇编指令推导，观测器不读取夹具的场景名、输入条件标签或真值。表中的路径语义用于人工解释和独立测试，不是为目标函数硬编码来源集合。

## 分层与观测选择

- `scripts/bounded_numeric_flow.py`：语言无关的有限无环整数指令依赖模型。适配器提供寄存器/栈来源种子、查询寄存器以及显式调用契约。它不理解 Go 的 Money 类型、测试用例名称或 eBPF。
- `scripts/path_observation.py`：按输出来源集合划分路径，贪心删除不再需要的分支。此前字段复制核心也使用同一个选择器。Sum 同时利用观测到的返回位置区分返回路径。这里只是有限模型中的包含极小集合，不宣称全局最优。
- `sum_adapter.py`：Go 1.25.4 amd64 的 Money 值参数/返回 ABI，目标 DWARF、寄存器保存指令和 ELF 字节校验，以及 BPF 事件适配。
- `string_capture.py`：复用已有 BCC 生命周期、PID namespace 过滤、G 身份、事件完整性检查和归档。

Go 的第一个 Money 使用九个参数寄存器，第二个 Money 通过栈传递；从实际布局验证 Units/Nanos 偏移，再结合已检查的栈帧和保存指令生成读取位置。该 ABI 是显式配置并验证的，不是通用 ABI 自动恢复。

正常优化的本地测试 ELF：27 条静态路径（可能保守含不可行路径）、11 个条件跳转，保留其中 3 个。

| 策略 | 物理探针位置数 | 成功用例预期结果 |
|---|---:|---|
| all_branches | 15：入口 + 11 分支 + 3 返回 | 精确来源集合 |
| selected | 7：入口 + 3 分支 + 3 返回 | 与 all_branches 相同的精确来源集合 |
| boundaries | 4：入口 + 3 返回 | Units 保留两个候选来源集合 |

**位置数不是单次事件数**：一次调用只到达一个返回位置，分支也不一定全部执行。没有据此宣称运行开销降低。返回错误的用例应报告 `rejected_input`，不把错误路径的零值解释成成功金额的来源。

## 调用与支持边界

明确假设：固定上游代码的 `money.IsValid` 与 `runtime.memequal` 不改写调用者参数/栈保存区；它们返回后的通用寄存器全部视为未知。此处利用只读调用契约，没有完成对全部被调代码的二进制证明。未知调用拒绝分析。

建模 Go ABI 的 X15 零值 SIMD 寄存器用于结构体初始化。不是一般 SIMD 支持。当前只做一个 Sum 调用，不支持循环、任意堆别名/写入、异步修改、任意结构体 ABI、跨调用合并、数据库或网络字段映射。符号与 DWARF 必须可用。最多枚举 256 条路径，未做条件可满足性求解。

## 运行与返回文件

沿用之前的 Go 1.25.4、Linux/WSL2 BCC 环境，无需 Docker。仓库根目录运行：

```bash
git pull --ff-only
sudo env "PATH=$PATH" GOPROXY=https://goproxy.cn,direct \
  /usr/bin/python3 experiments/checkout-money-sum/run.py run
```

共十个用例、三种策略、30 次采集：七个成功用例覆盖同值、进位、负数、两种符号校正、相消及全零；三个错误用例覆盖非法小数范围、符号不合法、币种不一致。真值为独立的字面量结果/来源表，在推断结果写出后才读取。

结束或失败时均打印 `checkout-money-sum-时间.zip`。请返回该文件，其中包含目标 ELF、汇编、静态模型、三种计划、原始事件、推断、真值和命令日志。

仅本地检查：

```bash
python3 experiments/checkout-money-sum/run.py build
python3 -m unittest discover -s experiments/checkout-money-sum -p 'test_*.py' -v
```

支持 `--checkout`、`--go` 和 `--output`。本地已完成：原始函数正常优化编译、ELF/DWARF/保存指令校验、十个原生用例及 15 项单元测试；此前字段选择/覆盖的 17 项测试通过。**尚未执行本实验的主机 eBPF 采集，不能将本地 build 成功说成动态溯源已通过。**
