# ngiflib 修复版本的正常数据流验证

## 范围和当前结果

沿用 HardTaint 评估中出现的 ngiflib 项目，研究相关解码路径的输入来源；本轮使用包含公开修复的固定提交和正常图片。**没有运行 PoC、异常图片或旧漏洞版本，没有复现漏洞，也尚未完成来源推断。** 这是修复版本的正常路径验证，不能记入 CVE 检出数或来源准确率。

固定源码：`cfbedecfeca66e22b62c37b85fcad5aa825625d7`。

修复关联证据：CVE-2018-11575 的公开记录指向上游 issue #4；上游提交 `be4c7dffdcf7543fe24acc7448d6014a939fd26b` 明确标注 “Fix #4”，增加解码码值的范围检查。已通过 Git 祖先关系确认本轮固定版本包含该修复。当前固定版本还包含其他后续修改，不声称仅相差这一处补丁。

原始 `gif2tga.c`、`ngiflib.c` 和 `ngiflib.h` 从固定 Git 对象读取，未修改源代码，也没有用自写函数代替解码逻辑。

2026-10-10 验证结果：

| 检查 | 结果 |
| --- | --- |
| 普通输入 | 4 张正常调色板 GIF：单像素、条纹、棋盘和色块 |
| 原始转换程序 | 4 张 × 真彩色/索引色两模式，8/8 输出逐像素一致 |
| 正常路径覆盖 | 单独覆盖率构建运行条纹图，修复检查执行 13 次，拒绝语句执行 0 次 |
| 来源集合 | 尚未采集、推断或评分 |
| Sanitizer | 编译成功，执行受 LeakSanitizer 所需 `/proc` 访问限制影响，未完成；不报告通过 |
| 漏洞复现/检测、性能 | 均未评估 |

普通图片由 Pillow 生成，并由 Pillow 重新解码确认像素；转换输出使用独立的无压缩 TGA 头部、调色板和像素解析器逐项核验。此前 Pillow 的 TGA 读取器对短于可选 footer 的极小图片报错，因此验证器直接按 TGA 的实际头部和负载读取；未修改上游程序或输入来隐藏输出差异。

机器可读结果：`normal-validation-20261010.json`。覆盖率构建与普通构建分开，覆盖率计数不是 eBPF 事件，也不是来源精度或性能证据。

## 第一条来源查询

目标不是“程序输出是否与输入相同”，而是：

> 对一次正常解码执行，`GetGifWord` 返回给 `DecodeGifImg` 的某个码值，其显式数据来源包含哪些输入压缩数据字节？

静态路径为：文件读取进入缓冲，`GetGifWord` 消费缓冲与残留位状态，通过移位、组合及掩码生成码值，`DecodeGifImg` 使用该值进行状态判断及边界检查。

来源粒度先限定为声明的压缩数据字节；字典状态、码宽配置、对象地址与控制条件分别记录，不自动混为一类。输出粒度是指定调用实例的返回码值，不要求相同数值必须来自相同字节。需要明确“字节级指令依赖”和“最小位级依赖”的差别，不能拿位级最小集合直接评判普通字节污点引擎。

当前覆盖率确认正常输入到达修复检查，**不提供每次 GetGifWord 返回的标签或精确来源**。下一阶段需要对固定 ELF 核验参数/返回 ABI、缓冲区版本和目标位置，再接入双方的来源采集。真值必须来自独立的格式解析/参考记录，并与实际调用实例对齐；不得以我们的选择器或 libdft64 输出充当真值。

## 尚需实现的部分

- C 的变长字节区域、16 位返回值、移位/掩码及跨调用状态支持，不能硬套原 uint32 夹具。
- 原始文件读取、stdio 缓冲和上下文残留位的版本绑定，避免把复用地址视为同一来源。
- 对同一个声明范围设置我们的采集与 libdft64 边界；未知指令、库行为和缺失事件仍报告 unknown。
- 在修复版本和正常输入上核验来源集合后，再讨论性能；当前不准备或运行异常输入。

`cut/join` 候选保留已有预注册和原生输出记录，接入工作暂停，避免同时扩大应用范围。

## 复现正常功能检查

已有 ngiflib 源码仓库并包含上述固定提交时，可运行：

```bash
python3 experiments/ngiflib-patched/validate_normal.py \
  --source /path/to/ngiflib \
  --output artifacts/ngiflib-normal
```

需要 GCC、gcov、Git、Python 和 Pillow，输出目录必须不存在。脚本仅生成正常图片，使用完整原始转换程序；在当前开发环境中已运行，不需要用户重复已有检查。
