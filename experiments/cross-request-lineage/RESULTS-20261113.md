# 第一轮结论：存在可重复的系统缺口，创新尚未成立

TraceFusion 当前配置不能完成这些严格的外部字段来源查询，结果可重复；但本轮不能证明这是一项现有基线不具备的新能力。MirrorTaint 已在真正以 B 为外部入口的单 JVM 缓存诊断中正确完成请求／字段来源查询，包括同值覆盖和新对象替换。后续值得研究的是完整 A→B 通信证据下的历史字段来源与版本查询，而不是笼统的“跨请求缓存污点”。

开始时 HEAD 为 `22664f392b17a033d089994d7b1ea926974befeb`，main，工作区干净；适用指令为仓库根 [AGENTS.md](../../AGENTS.md)。本轮未修改既有分析核心、Agent 或框架契约，1101 份现有 `.java/.py/.json` 文件哈希保持；只增加本目录实验与 Git 忽略例外。按要求提交、不 push。

主实验固定来源为 A 收到的真实外部 HTTP 输入 `/value`、`/fallback`，粒度为请求出现加字段。B 解码、读缓存和输出均不能重设 source。每组中的不同 trace ID 请求共享相同的两个业务 JVM；每个服务使用一个持续工作线程。没有清理分析状态、人工搬标签、业务对象污点字段或按值匹配来源。预期先冻结，再构建和运行；分析器不读预期。op/key 属于控制选择，本轮只评分显式数据来源。

TF 首次受支持分析的具体错误为 `control-write-address: Conditional nested write lacks a pre-branch reference witness`。原始六组的最后查询均保留为 unknown／分析限制，没有改核心或筛除失败。为便于检查，主评分 JSON 同时保留第六组完整证据业务副本的来源评分；六个完整副本合计 TF 12 unknown，MT 10 来源不匹配、2 常量空集合一致。第六组派生缺证义务单列，不能把其完整副本的分数当作缺证能力成绩。

受支持主实验的 36 个业务配置、96 次外部请求全部完成；响应、异常和缓存最终状态均与 plain 一致。六组对象／字段版本观测均匹配独立预期；实际发送／接收 HTTP 头与 JSON 字节、每组 PID／线程持续性、每个请求 trace ID 不同均通过独立复核。正常写版本被观测到不等于已经恢复了其跨请求来源。

主机 8u512 的更早首次分析也保留：12 个最后查询均因 `Application runtime pin differs` 拒绝，属于配置／运行时契约问题。随后只把三种模式统一切换到既有支持的 8u504，没有修改契约。此前还有一次 sandbox socket 权限失败和一次实验 DTO 缺默认构造器的 plain 失败，均单列保留，未计作分析传播错误。

为区分原因，另运行两个有明确边界的诊断，没有替换上述首次表：

| 能力／配置 | 当前 TF | MirrorTaint 原生 API＋薄适配 | 解释 |

| 缺写证据保护 | 主实验派生副本拒绝，但更早错误遮蔽；只读诊断本来就缺帧外写值且 unknown | 本在线 API 没有同样的离线写证据输入，N/A | 仍需在可回答正例上检验缺证退化，不能宣称已验收 |

诊断共 72 个业务配置、192 次请求，响应和最终缓存与各自 plain 相同，重复结果一致。直接 B 的 source 是 B 真正收到的外部 HTTP 请求；没有从 A 搬标签或把 B 内部反序列化伪装成外部源。MT 两个同值字段及不同请求的原生标签确实能区分，缓存原对象持续存在，未调用 shutdown／clear。另有四项独立证据审计负例：篡改预期、重复使用真实 RPC 头、重复原生 heap startup、篡改 codec wire 哈希，重新计算文件校验和后仍均被语义审计拒绝；这些审计不等于核心缺写来源保护已成功。

只读诊断具体暴露了观测范围：现有 `Recorder.fieldObserved` 在查询帧外更新版本计数，但不输出写值。既有离线应用分析又在每个根请求创建 `State`，只从该请求的 `binding-input/source` 构造 providers。因此这些诊断尚不能单独归因于一个纯离线算法错误；观测范围、根请求状态复用和通信来源查询都需要分开研究。miss 的本地 `/fallback` 可出现在原始 origins 中，但整体仍 unknown，也按 unknown 保留。

DisTA、Galette 的所需工件、JDK、native 通信／JCL 插桩、source/sink、同值控制及字段版本查询条件见 [基线准备说明](BASELINES.md)。DisTA 工件地址当次返回 404，未运行；Galette 本轮只核对已有原版／修改版兼容性记录和官方文档，未将旧成绩移用。两者均不计传播错误或 TF 优势。
